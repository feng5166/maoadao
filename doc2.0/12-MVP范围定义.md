## 零、要证明什么：总假设与五个子假设

> **「摆下一样东西，等着看看会来谁」本身足够产生持续回访；
> 而猫的稀缺性、资源价值和可研究规律，能够进一步形成七日目标链。**

| 假设 | 成立的证据 | 判决口径 |
| --- | --- | --- |
| H1 放置有效 | D1 阶段达成（首 session 完成"摆→等→发现"首闭环，16 欢迎结算保障） | 达成率 + 达成时长 |
| H2 未知有效 | D3 阶段达成（岛猫册出现未解目标；翻册→布置变更转化，18 北极星之二） | D1 完成者中的 D3 达成率 |
| H3 规律有效 | D5 阶段达成（为某只目标猫主动调整配置，17 干跑口径的真人版） | 留存用户中的 D5 达成率 |
| H4 经济有效 | D4 阶段达成（首次自主 Sink：资源→下一件物件目标，19） | 达成率 + 首次决策时长 |
| H5 收集有效 | 持续存在"想遇见/确认/搞懂的猫"（unresolved target 的存续） | 存续率（观察窗口内） |

判决结构（口径先冻结，数字后定）：

- **总留存粗线**：Day7 留存 ≥ 20%（种子阶段"值得继续迭代"线，粗线候选）；
- **Dx 漏斗分层是主判决工具**：对比"达到 D5 的用户"与"只到 D2 的用户"的
  Day7 留存差——**分层差异比单一均值更能说明玩法是否成立**；
- 各 H 的数字线**发船前在 22/观测台定稿**（结合种子规模与基线），
  本篇不预设精确 KPI——但发船前必须定稿，不带着空判据发船；
- D0（进入）不新立假设：已上线，完成率/跳过率继续观测；
  旧判据 `adopt_complete ≥60%` 等随旧 D1 链路**退役**（解冻记录）；
- "生命感/不像机器"不设数字假设——由三个北极星盲读看守
  （16 悬念盲读 / 18 观察笔记盲读 / 19 矿机化盲读）。

## 二、绝对不证明什么（举证责任外，v1 结构 KEEP）

1. **付费与商业化**——MVP 不收钱、不挂 SKU（19 已立真钱边界，闸门不开；
   验证期的钱只会污染数据）；
2. **多人与社会化**——兴趣组/串门/世界猫跨院全部第二阶段（21 只有框架）；
3. **深关系与情感归属**——落笔/命名→回应已归档（02 批次二），
   **D7 不测"某只猫对我特别了"**；牵挂/归属是玩法验证通过后的下一层命题；
4. **生态/跨家庭/Petverse**——远期；
5. **世界猫单实例的最终形态**——README §九·1 归 21 拍板，
   MVP 用从严一致性即可。

MVP 数据无论好坏，都不构成对以上任何一项的证明或证伪。

一句话收束：**MVP 只证明一件事——"摆个东西，等等看谁会来"
是否足以让一个人一次次回到自己的院子。**

## 三、绝对不做（即使很诱人——数据低迷时的纪律，v1 精神续作）

| 诱惑 | 说辞会是 | 判决 |
| --- | --- | --- |
| 签到/连续奖励/体力 | "提升日活" | 08 冻结：等待就是玩法本身 |
| 每日任务/目标引导 | "用户不知道干什么" | 开放端是材料不是任务（16 §七）；修引导文案，不加任务 |
| 硬造来访 | "发现率太低" | 16 冻结：Director 永不硬造 CatVisit；先查供给面 |
| Director 暗手推猫 | "留存要救" | 17 §七 冻结：普通来访没有第二只手 |
| 完成率/图鉴进度条 | "收集要可视化" | 18 冻结：可示已认识，禁示还差多少 |
| 稀有=高产落表 | "数值好配" | 19 冻结：Rarity × Value 正交 |
| 卖鱼/卖加速/卖概率 | "有人愿意付" | 19 冻结：真钱不买世界响应速度 |
| 指定猫必来/召唤 | "给用户确定性" | 16/17 冻结：发生权无结果权 |
| 提前上多人 | "社区拉留存" | 21 第二阶段冻结 |
| 加剧情高潮救内容 | "太平淡了" | 06 反小剧本（批次二适配后仍有效） |

**低数据的合法应对路径只有一条**：先诊断四环哪个枯了
（探索/研究/经济/收集，配合 10 四因子）→ 修供给与节奏 → 一轮再测。
**改世界规则永远不是应对数据的手段**（v1 原句）——规则要改，
回对应文档解冻重议，不在数据压力下现场改。

## 四、决策门（种子期结束，三档，v1 结构 KEEP）

- **继续**：总留存过线 + Dx 分层显著（D5 达成者留存明显更高）+
  北极星盲读通过 → 进入深化（批次二/三全量 + 第二阶段规划）；
- **调整**：介于两线之间 → 按 §三 纪律修供给修节奏，一轮迭代再测，不动规则；
- **重做**：远低于粗线，且 Dx 分层无差异（玩得深的人也不留）→
  回命题层重议——那时怀疑的是命题，不是把产品往老虎机改。

定性信号同权重：能叫出几只猫的名字 / 有"想等的猫" / 把册子翻给朋友看 /
站外自发讨论规律（兴趣组的萌芽形态）/ 催问"还有没有新猫"。

## 五、可以糙的地方（反向豁免，防过度打磨）

猫社会深度（D6 供给薄，同现/岛闻带过即可）· 抓拍（可后置）·
特殊材料与特殊交换（可后置）· 打理深度（一态切换即可）·
行为/物件生活史的独立视图（逻辑记录先行，UI 后置——18 单入口已定）·
新音效包 · 性能极限优化 · 分享卡。

**打磨预算全部让给：D1 首闭环的 5 分钟、来访与痕迹的表达质量、
岛猫册条目的质感。**

## 六、范围变更三关（v1 KEEP）

命题相关性（五假设之一）→ 最小集必要性（§一 缺它则某个 H 测不了）→
对应文档红线。三关全过才进；口头理由不算。
**砍功能永远不需要开会，加功能才需要。**

## 七、开工判据：批次一收口即回答"该开始做了吗"

开工三前置：

1. **20 冻结**——Dx 完成旗标是全部 H 判据的度量地基；
2. **22 首版**——猫池构成 / 物件与标签 / Window 粒度 / pacing 的骨架表
   （不必完美，够开工即可；22 是实施期滚动文档，建议排在 20 之后立首版）；
3. **14 尾部接缝方案**——D0 → 院子的交接屏与旧链路清扫清单
   （文档修订可留批次三，接缝设计先行）。

三者齐 → 开工。批次二（01/05/06/09/02/10）与实施并行推进——
它们回答"原模拟器怎么支撑新玩法"，不阻塞动工。
