## 一、D0 要回答用户脑中的四个问题（v3 修订）

1. **这里是什么？** 有猫、有岛；猫有自己的生活；世界会持续变化——
   **即使没有你，它也在运行**。
2. **我是什么身份？** 不是主人、不是玩家、不是操控者——
   **岛上的新岛民：你在这里有一个自己的院子**（不是"某只猫的主人"）。
3. **这里有什么体验？** 体验承诺，不是功能列表：**在自己的院子里摆下点什么，
   等等看谁会来** / 观察一个岛每天发生的小事 / 慢慢认识这些猫和这个岛。
4. **为什么值得留下？** 这里有一些生命，即使没有你，也会继续生活——
   而你的院子，会慢慢攒下只属于你的经历。

## 二、七仔在 D0 的职责：猫岛体验样板（v3 语义校准）

迪士尼米奇式——米奇不说"成为我的朋友"，米奇说"欢迎来到这个世界"。三个展示：

1. **猫有自己的生活**（整理收藏、去海边、与别的猫擦肩）——猫不是按钮；
2. **猫会回应，但不会服务**（你靠近，它看一眼，继续做事，过会儿从你脚边走过）
   ——这里不是 AI 助手；
3. **猫岛有温度**（小屋、物品、别的猫、旧物）——这是一个生活世界。

**v3 明确（防旧语义回流）**：七仔演示的是"岛上的猫怎么生活"，
**绝不暗示"这只猫（或任何一只猫）将属于你"**——它是样板，不是预告；
它给用户看的是"猫会按自己的偏好被东西吸引"（瓶盖！），
这正是院子玩法的种子画面。

## 三、五幕走片（180s，全员统一心流，零分支）

**幕一 · 进入（0-20s）——"这里是什么地方？"**
- S0 船票（8s，评审细化：**已寄到的邀请，无领取动作**）：打开页面，
  船票已经躺在纸面上——没有"获得"、没有点击领取、没有新手礼包，
  你只是发现自己被邀请了。一行字："你的船到了。"〔登岛〕
- S1 码头（15s）：三行字浮现 + 沙地脚印。〔跟上去〕；
  右下小字"直接去见它"（唯一跳过口 → 直达 D1）

**幕二 · 岛在运行（20-60s）——"这里真的在运行"**
- S2 沿脚印穿过岛：公告栏贴着今天的岛闻，报摊正在换新一期《猫啊岛日报》
- S3 远景一屏：几只猫各自过日子——有的晒太阳，有的往渔港去，有小屋亮着灯

**幕三 · 七仔 = 生命感（60-120s）——"这只猫不是 NPC"（v3：分镜照旧，语义校准）**
- S4 脚印的尽头是它：捡起一枚瓶盖，先用爪子拍两下，叼起来
  （**偏好的种子画面**：一样东西吸引了一只猫——不用说破，画面已在教玩法的根）
- S5 木箱边那排收藏——它把其中一件挪了个位置
- S6 **轻触点（D0 唯一交互）**：〔蹲下来看看〕→ 它抬眼看了你一下，
  继续手上的事；片刻后，它从你脚边走过去了。
  （回应，不服务。没有戏剧、没有等待、没有"它回来了"——只有日常。
  **它不是在认识你，它只是没被你打扰**——v3 删除一切"相认前奏"的解读余地。）
- S7 路过将军，互相碰了碰鼻子，谁也没停（**它们生活在同一个岛上**——
  社会感的一瞥，不是"关系的可能"预告）

**幕四 · 未来体验（120-160s）——"我在这里会有一个自己的地方"（v3 重写）**
- S8 院子的小屋（**结构 aha 锚**；分镜照旧：它把瓶盖放在门口，退两步，
  门牌是空白的——2.1 语义 = **这就是你的院子**）。
  旁白三行**全部换轨**（体验承诺，现在时）：
  旧三行 DELETE（"会有一只猫慢慢认识你"= 单猫承诺，v3 清除）；
  新三行（**2026-08-09 终审冻结**）：
  **"这个院子，以后就是你的。／摆下点什么，偶尔会有猫按自己的性子来看看。／
  你不在的时候，这里也会发生一点事。"**
  （评审改定：加"偶尔"——D0 与真实 Yard 的等待感一致（17 有条件+有概率+
  空窗合法）；"来看看"不把猫的行为收窄成"坐坐"（它可能睡/闻/玩/路过/
  只留痕迹）。**三行到此为止，不加第四句解释玩法。**
  S8/S10 的"这里以后就是你的"语义重复暂留：S8 是认知承诺，S10 是完成引路
  的现实落点，作用不同——若走片听着啰嗦，从表演节奏处理，不重构。）
  （第一行给位置，第二行给条件权，第三行给"不由你决定"——四期待的后三个
  在此落地；第一期待"岛自己在运行"S2/S3 已给。）
- S9 理念收束（**语言 aha 锚**，独屏一句，照旧不动）：
  **「当现实世界太忙，总有一座岛上的猫替你慢慢生活。」**

**幕五 · 选择（160-180s）——§九 冻结版照旧**
- S10 完成引路：它经过小屋停一下、看一眼门口的瓶盖、回头看你、往码头去。
  「它回码头去了。院门虚掩着——这里，以后就是你的地方。」
  〔进院子〕→ `claimYard` → **真实 Yard**（§九 全部工程红线照旧）

### ⑤ 工程红线（评审补入，随本节冻结）

1. **claimYard 幂等 + 单事务**：

   ```
   claimYard(user, ticket) = 验证 ticket + 原子核销 + 创建/取得 Home
     + 创建/取得 Yard + 初始化 YardSlot + 发放初始 Goodie + 登记岛民身份
   ```

   要么全成功，要么全失败；重复/并发调用只能得到同一个 Yard——
   不多核销船票、不多发初始物件、不多建院子、不多写岛民记录。
   **CI（上线前必过）：同一用户并发/重复执行 claimYard，
   最终 Home/Yard 唯一，初始资产恰好一份。**
   （承 v1"一次机会原子消费"不变量。）

2. **skip 口走完全相同的 claimYard**：`skip D0 → d0_skip → claimYard → /yard`
   ——**跳过的只是电影，不是身份建立**。d0_complete / d0_skip 是两种体验路径，
   `yard_granted` 是共同的世界事实；与 20"D0 在 Reached 链外"吻合，
   skip 用户的 D1–D5 数据完全可分析。

3. **hasYard 是用户侧唯一主身份信号**：用户侧居民态 = `hasYard`，
   此后不得再出现 `hasCat ? resident : newcomer` 式判断；
   历史 `hasCat` / `viewerCat` 转 BACKEND_ONLY，**不得继续参与首页路由、
   身份判断、D0 是否播放、海螺主对象判断**——否则旧模型会从边角重新长回来。
   开工首周扫词升级为 **migration CI / checklist**：
   `hasCat / viewerCat / ownerCat / adoptCat / /adopt / /my-cat`
   逐个判断"是否仍影响用户侧主流程"并记录处置。
