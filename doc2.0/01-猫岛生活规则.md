## 一、猫每天如何生活——一天的形状〔已运转〕

岛上的一天分三段：上午、下午、晚上。事实在清晨一次性发生（tick），
但对你**按现实时段浮现**——早上只看得到上午的事，下午的事下午浮现，
晚上由日记把一天收起来（doc/14）。世界不为你暂停，也不等你。

一只猫的一天由五件事构成：

| 事 | 世界观语言 | 机制出处 |
| --- | --- | --- |
| 睡 | 猫的大半天在睡觉——**睡觉是正当生活，睡姿和梦是正当内容** | 干跑 rest 占 23.4%；睡姿/梦境池（doc/09） |
| 做自己的事 | 有职务的做职务（爆米花编报、球球看店），没职务的忙自己的 | NPC 四型分工（doc/00 §八） |
| 小习惯 | 习惯是**活出来的**，不是设定的——"它最近总在下午去码头" | 地点/时段统计派生，零新状态（doc/09 §六） |
| 碰见谁 | 每天零到一次社交，关系从碰见里长 | 三时段模拟（doc/00 §四） |
| 捡东西 | 全岛的猫都会带回它觉得重要的东西（岛的规矩） | 叼回小东西，约 3–5 天一件（doc/21 §五） |

质感标尺（doc/09 原判据，日更执行）：**小事要小得具体、具体得无用**——
不是"捡到一片树叶"，是"追了半个岛，最后只找到三片"。
eval 红线照旧：每天每猫至少一件值得看的小事。

## 二、猫之间如何建立关系〔已运转，呈现层待强化〕

三条规则：

1. **关系从事件里长出来，不从数值里长出来。** 相遇 → 又相遇 → 一起经历了一件事
   → 称呼变了。用户看到的永远是事，不是进度条（用户侧禁裸数值，doc/05）。
2. **结果由世界裁决。** 想借钱可能被拒，想帮忙可能帮倒忙（模拟器是唯一事实来源）；
   允许"合不来"——冲突是轻喜剧，不是狗血（doc/07 D5 低强度受挫原则）。
3. **一段关系靠三种方式被看见**：交叉视角〔已运转〕（同一件事两只猫各说各的）；
   称呼变化〔已运转〕（从"那只新来的"到名字，到只有它们之间的叫法）；
   岛闻合并出现〔已运转〕（两只猫开始成对出现在岛上生活里）。

样例——回答"七仔怎么认识小橘"这类问题的标准形状（先有一件事，再有一段关系，
最后才有一个称呼）：

> 小橘的风筝线断在松林。七仔把缠成一团的线叼回了码头。
> 第二天小橘来找线，在木箱边坐了一下午。
> 现在小橘管七仔的木箱叫"那边"，管自己家叫"这边"。

## 三、岛上有哪些固定习俗〔增量：本文的主要新贡献〕

**习俗判据三条**（先于任何具体习俗，防运营化）：

1. **习俗是岛自己过的，不是办给用户看的**——没有活动入口、没有报名、没有倒计时；
2. **错过零惩罚**：永不出现"昨天是赶海日你错过了"（好奇不是愧疚，doc/24 §三）；
3. **必须产生内容差异**：习俗日的日记/岛闻读起来和平日不一样，否则就是空设定。

### 已存在的习俗（翻译）

- 《猫啊岛日报》每天清晨出摊（cron 就是世界的作息）；
- 全岛的猫都把重要的东西带回家（岛的规矩，IP 认知底座）；
- 七仔每天傍晚把收藏排成一排数一遍（个体习俗即内容模板）。

### 新增提案（首批三个，宁少勿多）

| 习俗 | 内容 | 机制增量 |
| --- | --- | --- |
| **大退潮日**（约每周一次） | 潮退得特别远，全岛的猫往海边去，捡到东西的猫变多 | 导演加周期权重：当日拾获/海边事件上调，叼回小东西概率上调；岛闻当日头条固定为潮讯 |
| **休刊日**（低频随机，约两三周一遇） | 爆米花也要休息。公告栏只有一行手写的："今天没有新闻。天气很好。" | 日报 cron 低概率跳过 + 固定文案池；**"安静"本身成为质感**。评审修订：不设固定周几——低概率才有仪式感，太频繁会显空；该句可作**猫岛气质代表句**用于对外物料 |
| **雨天**（天气即习俗） | 雨天全岛节奏慢半拍，每只猫有自己的雨天去处（七仔在木箱，正典已有） | 天气状态接入事件权重；派生统计让"它不喜欢雨天"可被用户发现 |

评审补充（2026-08-05）：三个习俗全部通过。大退潮日与七仔天然绑定——
**「每次大退潮，它都会找到一些奇怪的东西」**可直接成为内容号的系列节奏。

远期候选（仅记名不拍板）：岛屿节日（doc/00 二期共创区）；
"岛的生日"涉起源层——00 已冻结，另文讨论。

## 四、用户如何参与但不控制〔已运转，收拢成"居民公约"〕

参与总判据（doc/21）：**结果由猫决定的可以做；由用户操作/资源决定的不做。**

现有的五只手：

| 手段 | 形态 | 猫的自由度 |
| --- | --- | --- |
| 留一句话 | 今晚说，明早它带着自己的决定回你（三段兑现铁律，doc/19） | 采纳与否都成立 |
| 二选一 | 基于当天真实捡到的小物 | 它执行，但有自己的方式 |
| 摸摸它 | 轻接触，确定性反应池 | 心情决定反应 |
| 看岛 | 岛景一瞥/"岛上今天怎么样" | 纯观察 |
| 物件命名 | 给它捡回的东西起名字，进长期记忆 | 名字它认，用法它定 |

留痕三通道边界照 doc/23：对你的猫说话（私有，被记住）；在岛上留下东西
（公共，可能被七仔捡走，不建记忆）；和猫共同做一件东西（P3）。

公约底线：**关系不可购买**（好感无数值可充）；缺席时世界继续，
回来不被责备——它把最想说的一件先讲给你（doc/07 缺席原则）。

## 五、什么事件让用户每天回来〔已运转 + 本文统一公式〕

**回访公式：确定的小满足 + 不确定的小惊喜 + 未完成的小牵挂。**

| 成分 | 定义 | 落点（全部已上线） |
| --- | --- | --- |
| 确定的小满足 | 任何时刻打开，都能看到"它现在怎么样" | 此刻状态行 + 时段解锁（一天三个打开理由） |
| 不确定的小惊喜 | 今天可能有、也可能没有的那件事 | 叼回小东西（3–5 天）、第一次系列、Life Moment 微细节 |
| 未完成的小牵挂 | 昨晚留下的那半句 | 三段兑现（今晚问→明早答）、事件线推进（15%）、D2 承诺 |

节律叠加：**日节律**（时段解锁）→ **周节律**（习俗日，§三增量）→ **稀有节拍**
（大事件 10%、D7 纪念册、月册）。三层节律错开，避免"每天都一样"。

红线重申：以上全部是**拉力**。任何一条变成推力（催促、倒计时、损失厌恶），
即违反 doc/24 §三·7"好奇不是愧疚"，eval 按 P0 缺陷处理。

**升格（2026-08-05 评审拍板）：回访公式即内容验收标准。** 任何事件进入猫岛前
问一句——它贡献了满足、惊喜、牵挂中的哪一个？**一个都不贡献的事件，不进入猫岛。**
（写入 eval，与"每天每猫至少一件值得看的小事"并列为内容底线。）

## 六、设计原则：无用即有用（Meaningful Uselessness）〔v1.1 创始人拍板增补〕

> **猫岛不追求让每个细节都有明确用途，而追求让每个细节都有存在理由。
> 那些看似无用的小事，恰恰构成了一个生命真实存在过的证明。**

核心：一个细节如果没有直接功能，但能让用户感受到生命、时间、关系和温度，
它就有价值。"无用" = 脱离效率/目标/奖励体系的存在，不是没有价值——
现实里人被"有用"包围（KPI/任务/效率），猫岛提供的是
"有些东西存在，不是为了完成什么，而是因为它本来就在这里"。
这正是猫阿道建岛的理由（00 起源），也是用户进岛的理由。

血缘：doc/09 的素材标尺"小得具体、具体得无用"是本条前身——
此次从素材标尺升格为**产品设计最高原则之一**，并补上删除判据与溯源边界。

### 删除判据（新增设计判断，与传统判断并用）

传统产品问："这个功能给用户带来什么收益？"
猫岛加问一句：**"如果删掉这个细节，世界是否少了一点生命感？"** 是 → 有价值。

### 正例四则

| 细节 | 传统视角 | 猫岛价值 |
| --- | --- | --- |
| 它傍晚把今天捡的东西重新摆了一遍 | 无收益、不能兑换 | 生命感——"它有自己的生活" |
| 休刊日："今天没有新闻。天气很好。" | 内容缺失 | 呼吸感——世界真实（§三已拍板） |
| 它路过一朵花，停了一会 | 无任务、无奖励 | 性格表达 |
| 收藏里一颗贝壳摆错了位置 | 无任何影响 | 不完美的生命——"原来它也会这样" |

### 反例三则（红线）

- **不为"有内容"制造内容**：❌ 七仔日更十条动态 → 变运营账号；
- **不为"互动"制造互动**：❌ 每次打开猫都跑来欢迎 → 猫变客服（doc/22 红线③同源）；
- **不为"留存"破坏生活**：❌ "今日任务：陪猫玩 3 次" → 变游戏（doc/24 §四 清单同源）。

### 无用服务三个方向

1. **展示生命**：打哈欠、晒太阳、发呆——"它真的在那里生活"；
2. **建立记忆**："第一次看到它整理收藏"——属于这里的瞬间；
3. **塑造世界**："即使我不在，这里也继续存在。"

### 边界：无用 ≠ 随机

每个无用细节必须有来处，三选一可指认：
**角色**（因为它喜欢收藏）/ **世界**（因为今天下雨）/ **关系**（因为你们经历过那件事）。
三者都指不出的细节是装饰，删。

### 与内容三问（§五）的关系

不冲突，两道门：无用细节正是"确定的小满足"的主要供给——**生命感本身就是满足**；
三问筛掉的是既无功能也无生命感的空事件，本条保证留下来的每件小事有存在理由。

一句话分界：普通游戏设计"玩家要做什么"；**猫岛设计"一个世界里本来会发生什么"。**
真正让人喜欢猫的，不是它完成了什么，而是它做了一堆毫无意义、但只有它会做的小事。

## 九、2.1 玩法化接口：Eligibility 世界侧（2026-08-08 增量立稿）

> 命题（创始人点题）：**到了某个 Visit Window 的起点，这只猫此刻究竟在哪里、
> 在做什么，以及它今天有没有真实理由出现在这个院子。**
> 只解决五件事，不重写生活模拟。09 给了"出生时是谁"，05 给了"经历留下了什么"，
> 本章是最后一环：把倾向落成**当天的世界事实**。

### 9.1 核心链（冻结候选）

```
Birth Canon / LifePatternSeed      → 09
LifeImprint / Familiarity          → 05
WorldState / Weather / Relations   → 01 inputs
            ↓ at WindowStart
CatWhereabouts（它此刻在哪）
CurrentActivity（它在做什么）
EligibilityReason[]（能来/不能来的世界理由）
            ↓
Eligible / Ineligible
            ↓ only if Eligible
Preference / Composition / Random  → 17
```

**第一红线（冻结）：Eligibility 回答"它有没有真实理由成为候选"，
Preference 回答"它有多想来"——两层绝不能混。**
"晚上更喜欢安静"是 Preference（可以低权重）；
"此刻在岛另一头做一件走不开的事"是 Eligibility（就是 0）。

**可读 / 禁读清单（评审修订，冻结——一次拆干净）：**

```
Eligibility 可读
├─ Birth Canon / LifePatternSeed（09）
├─ Eligibility-relevant LifeImprint（05：影响行程/可达的经历）
├─ WorldState / Weather / Relations
├─ Role / Route / CurrentActivity
└─ YardWorldFacts —— Placement Snapshot 中的硬条件事实
Eligibility 禁读
├─ CatHomeAffinity（只属于 Preference 修饰层，永不决定资格）
├─ Preference 权重
├─ 余额 / 付费 / Dx 旗标
└─ 原始用户动作
```

**YardWorldFacts 的关键区分**："用户刚点了旧木箱"不能作为 Eligibility 输入；
"Window 起点院子里**客观存在** old 物件"可以——老怪类硬条件由此有了合法归属
（读的是世界事实快照，不是用户操作流）。

### 9.2 五件事

1. **Whereabouts**：每只池内猫在每个窗起点有一个"此刻在哪"的世界事实
   ——由 LifePatternSeed（09 倾向）× 当日世界状态（天气/习俗/季节）×
   职务与路线派生。实现形态不预设（16 冻结口径），语义唯一：
   **行程是世界事实，叙事与结算同读一份**。
   一致性红线（评审修订，冻结）：**不可发生时间重叠与不可达位移**——
   不是同窗地点互斥：12:05 在渔港、13:10 到院子完全可以属于同一个 90 分钟窗；
   P0 是"12:00–13:20 明确在报社开工，CatVisit 却 12:40 出现在院子"。
   判定模型：`Whereabouts@WindowStart + CurrentActivity.occupiedUntil +
   位移可达性 + candidate.arriveAt → 是否世界一致`
   （世界模拟不被 Window 粒度绑死）；
2. **CurrentActivity**：它当时在做什么，以及**这件事允不允许离开**——
   v1 §一 的五件事（睡/职务/习惯/碰见/捡东西）就是活动池；
   活动带"可离开性"标记（睡重觉/执勤中=走不开；闲逛/散步=可以顺路）；
3. **WorldConstraints**：天气（雨天全岛慢半拍，v1 §三 正典接入）、时段、
   路线覆盖（它的活动半径罩不罩你的院子）、职务（见 9.3）、
   社会状态（MVP 薄供给）——全部作为 Eligibility 输入；
4. **LifePatternSeed → 今日实际行程**：09 只给倾向（"傍晚爱在高处"），
   01 把倾向结合当日条件落成事实（"今天雨，它午后就回屋了"）——
   **今天的行程可以偏离倾向**，偏离本身是生活（也是玩家"算不透"的
   合法来源之一，17 白名单"猫的当日状态"在此产生）；
5. **Eligibility Snapshot（冻结候选）**：窗口起点**一次性裁决并锁定**——
   `EligibilityReason[]` 随 16 的 WindowSettlement 快照同锁，
   晚算不得重取世界状态（"晚算不晚取"从布置扩展到世界侧输入）。

### 9.3 职务猫：role 产生时间与地点约束，不是硬名单（冻结候选）

**不做 `有 role → 不可来`。** 职务是行程约束：爆米花白天钉在报社（该时段
Ineligible，理由="在编报"），**打烊后路过你院子完全合法**——
09"驻点猫不入常规池或极低频路过"由此落成**世界规则**而非黑名单。
职务时刻表归 22/实施；老章特殊（登记处正典驻点，不入池照旧）。

### 9.4 附带产出：不来的理由是叙事资产（评审修订：加可知性裁决）

两种"没来"，性质不同（冻结）：

> **任一 Ineligible 必须可指认世界理由；Eligible 未命中不补理由。**

后者是"规律是主体，随机负责惊喜"（17）的领地——它只是这次没来。
硬给理由 = 为了圆随机结果**伪造世界事实**，禁。

理由结构带认知权限——引擎知道它在渔港 ≠ 用户可以知道它在渔港：

```
EligibilityReason { code, factRef, observability }
```

只有【岛闻公开过 / 用户目击过 / 合法公共世界事实】三类 observability
才能成为用户侧叙事；其余仅用于 simulation / debug。冻结句：

> **不来的理由可以成为叙事资产，但世界知道的理由必须先经过可知性裁决，
> 才能成为用户知道的理由。**（与 16 三层分离、18 认知镜像对齐——
> EligibilityReason 不许成为后台真相泄漏口。）

### 9.5 红线与 eval

- **两层不混**（9.1 禁读清单）：Eligibility 输入集经 CI 隔离审计，
  与 17"0 就是 0"互为两半；
- **行程由世界生成，永不由院子需求反推**——Director 对行程零写权；
- **一致性抽检**：按 9.2·1 时间重叠/可达性模型判，非同窗互斥；
- **理由抽检**：任一 Ineligible 有 reason；任一 Eligible 未命中**无** reason
  （出现即"伪造理由"缺陷）；用户侧出现未过可知性裁决的理由 = P0；
- **Snapshot 抽检**：同窗重复裁决结果一致（世界侧输入已锁）。
