# doc2.0/16 院子核心循环设计——放置、等待与结果的时间轴（Gameplay Bible）

> 2026-08-07 立稿（2.1 玩法化·批次一第 3 篇；上游：08 v2.1 冻结、README 2.1）。
> 边界继承：**08 定义人的循环，本篇定义这套循环如何真的运转。**
> 定性：**先定时间轴与状态机，不定概率公式**——概率与偏好（17）、收集（18）、
> 经济（19）、一切数值（22）都挂在本篇的骨架上；骨架不清，17 没资格谈概率。
>
> 要解决的六问（创始人点题）：放什么 · 放哪里 · 什么时候开始生效 ·
> 世界如何产生 CatVisit · 用户什么时候看到结果 · 一次结果如何转化成下一次期待。
>
> 架构守则（全批次适用）：院子循环负责驱动行为，世界模拟负责决定事实，
> AI 负责放大生命差异——永不为玩法概率跳过世界事实。

## 零、核心论点：循环的本体是两个时钟的咬合

- **世界钟**：worldDay × 结算窗口——事实在这里发生；
- **用户钟**：session（开门→发现→调整→离开，08 七拍）——发现在这里发生。

玩法 = 用户在自己的时刻，收世界在自己的时刻产生的结果。
两个钟永不同步，**这个错位就是等待的形状、悬念的来源**（08 §三）。
一切设计围绕保护这个错位：不搞实时喂养，也不搞"打开才发生"。

## 一、放什么：物件（六问之 1）

- 物件 = 院子里的实物，三重属性：**标签**（偏好匹配面，体系归 17）、
  **状态**（新旧、使用痕迹——可被发现，08 拍 2）、**位置适配**（哪些槽位放得下）；
- 获取与维护归 19（维护用世界语言："用旧了""该打理了"，永不 HP 条）；
  首发清单与成本归 22；
- 语言红线：用户侧永远是"**摆了什么**"，不是"用什么召唤/吸引"（04）——
  物件是生活布置，不是诱饵道具。

## 二、放哪里：槽位与位置差异（六问之 2）

- 院子 = 一张实景（11 Home Yard 母场景），槽位 = 场景里的**具体位置**
  （屋檐下 / 老树旁 / 空地 / 门口台阶……），不是抽象格子；
- 每个槽位自带位置属性（遮蔽/日照/高低/离门远近……标签体系归 17）——
  **同一物件放不同位置 = 不同实验**，这是"研究"环的空间维度；
- 初版 3 槽（README），扩槽是经济 Sink（19），节奏归 22。
  **槽位有限是设计**：限制才产生选择；
- 动作三个（08 冻结）：摆放 / 更换 / 收下；更换成本参数归 22，
  冷却不默认存在（08 冻结注记）。

## 三、什么时候生效：结算窗口（六问之 3）

- 世界日划分为**结算窗口**。MVP 沿用现有三时段（上午/下午/晚上）作为窗口，
  粒度可调归 22（如后续拆出清晨/深夜）；
- **摆下即生效于下一个尚未开始结算的窗口。** 当前窗口内的生活不重排——
  世界不为你重演（07 结果权的时间形态）；
- 窗口内的事实按现实时间浮现（继承既有三时段浮现机制——现有机制 KEEP，
  升级为窗口的浮现面）；
- **等待的三种自然长度**（README"短中长"的落地）——不是三种机制，
  是同一时间轴上的三种距离：
  窗口内（撞见此刻在场的猫）／下一窗口（数小时，常规实验）／
  跨日（条件类：天气、时段专属、稀有组合）；
- **D1 阶段特例（欢迎结算，一次性）**：第一次摆放触发一次加速结算（分钟级），
  保证 D1_COMPLETE 可在首个 session 内达成。这是导演调权重的合法用法，
  仅 D1 阶段一次，**永不成为常态机制**；
- 离线不暂停：窗口照常结算，结果与痕迹累积，不过期（08 §三）。

## 四、世界如何产生 CatVisit（六问之 4）

- **来访是世界模拟中的合法事实**（08 冻结口径）：实现形态不预设——
  location state / schedule / transition 皆可，唯一硬约束是**一致性**：
  同一只猫的行踪在世界叙事与院子事实之间不得自相矛盾。
  世界猫实例问题按 README §九·1 处理（倾向：身份唯一、实例不互斥、
  共享履历不共享硬占用；21 拍板，拍板前一致性从严）；
- **生成时机**：窗口开始时（或窗口开始后首次被查询时）按**窗口起点的布置状态**
  生成该窗口的来访。**确定性种子（yardId × worldDay × 窗口）**——
  查询多少次结果都一样：**刷新永不重 roll**（红线，CI 级校验）；
- **输入**（只定接口，公式与权重全部归 17）：
  布置状态 × 猫的偏好与状态 × 时间 × 天气 × 院子状态 × 社会状态 → 来访倾向；
- **来访稀疏是质感**：每窗口每院来访少量（0-2 只级，参数归 22）——
  天天满院，猫就成了刷新物（L2 反例）；
- 无来访是合法结算结果，且窗口仍可产生非来访发现物（§六）。

## 五、CatVisit 事实结构（六问之 4 续）

```
CatVisit {
  id, catId, yardId,
  window: worldDay × segment,   // 归属结算窗口
  slotId?, itemId?,             // 它用了哪儿、用了什么（可空：只是路过）
  arriveAt, leaveAt,            // 窗口内的时刻
  behaviors[],                  // 行为（池与生成归 17/10；必须允许无用行为）
  leftBehind[],                 // 留下的：小鱼干 / 纪念物（数值归 19/22）
  traces[],                     // 痕迹：压痕/毛/挪动/水位…（表达归 04 环境语言、11）
  recorded: full | trace_only,  // 允许"只有痕迹、没有记录"（08 拍 3；D2 不确定性供给）
  observedLive: bool            // 用户是否在场看到
}
```

- **behaviors 必须允许无用行为**（打哈欠/发呆/把你的东西挪歪）——
  结算之外的生命，L3 保留地（08 §四）；
- **trace_only 是设计，不是省内容**：比例与规则归 17/22；
  红线：不许用 trace_only 掩盖"没有内容"——痕迹也是内容，同样过 04 表达关；
- **observedLive 不带奖励差**：在场撞见是运气与体验，不是机制承诺，
  更不是"在线更划算"——那会把等待变成蹲守。

## 六、用户什么时候看到结果（六问之 5）

- 已结算窗口的一切，开门即可见——不做逐条解锁的动画排队；
- 进行中的窗口：此刻在场的猫可被撞见（observedLive）；
- 结果六类（README）：看到当前猫 / 来过的痕迹 / 新猫解锁（岛猫册，归 18）/
  资源 / 新行为 / 猫之间互动；
- **结果节奏保障（08 冻结口径的系统化）**：每次回访至少一件可发现的事，
  且**可发现 ≠ 来访**。供给面按序：来访（有则最强）→ 旧痕迹的变化 →
  物件状态 → 环境变化（天气/时段痕迹）→ 岛闻。
  **Director 永不为凑节奏硬造 CatVisit**；真的安静时，"今天很安静"本身
  要被可感知地表达（休刊日精神：安静也是质感）；
- 收下（08 拍 4）：逐件发现式，不做一键收菜；不腐烂、不过期。

## 七、一次结果如何转化成下一次期待（六问之 6）

机制原则：**每个结果至少携带一个开放端——但开放端是材料，不是任务**
（08：只提供材料，不派目标）。四类开放端：

1. **行为即线索**："它在纸箱里待了很久" → 暗示偏好。线索的信息量归 17 校准：
   **能学，但一次学不完**（规律是主体，随机负责惊喜）；
2. **岛猫册的未知槽与未补全观察**（18）：看见即目标感，永不倒计时；
3. **新物件的可能性**（19）：资源攒到某处，自然想到"换了它能试什么"；
4. **岛闻线索**（01/03 管线）：别处的猫的说法 → "会不会来我这儿"。

红线：开放端永不写成任务句——"试试把纸箱放到屋檐下"这类句式禁
（那是攻略腔，不是世界；04 词典）。

验收句（与 08 拍 7 同一句）：离开时的念头是且只是——
**"我换个东西，下一次会来谁？"**

## 八、状态机（系统侧）

```
布置态 ──摆放/更换──▶ 生效等待（下一窗口起点）
窗口起点 ──世界结算（确定性种子）──▶ 窗口事实（CatVisit[] + 发现物）
现实时间过窗 ──▶ 可发现（开门即见；在场可撞见 observedLive）
用户开门 ──发现/收下──▶ 回到布置态
（离线：窗口照常结算，结果累积，不过期）
（D1 特例：首摆 → 欢迎结算，一次性）
```

红线汇总：刷新不重 roll（确定性种子）· 摆放只影响未开始的窗口 ·
无召唤类机制 · 冷却不默认存在 · 来访必须是世界合法事实 ·
结果节奏不硬造来访 · observedLive 无奖励差。

## 九、eval

- **确定性抽检**（CI 级）：同窗口重复查询，结果逐字段一致；
- **一致性抽检**：抽任一 CatVisit，该猫同窗口的世界叙事无矛盾
  （日报说它在渔港、它却在你院子 = 缺陷；21 拍板实例规则前从严）；
- **时间轴抽检**：摆放生效于正确窗口，当前窗口不受影响；
- **结果节奏抽检**：连续多次回访零发现 = 缺陷；
  来访率随回访频率上升 = **P0**（硬造来访的证据）；
- **悬念盲读**（定性）：抽 session 结尾，能否指出
  "这个用户下一次想试什么"——指不出 = 开放端供给失败。

## 合回清单

### 数据模型
Yard / YardSlot（位置属性）/ Placement（含生效窗口）/ CatVisit（§五结构）/
发现物与收取状态。
### Simulation
窗口结算管线（确定性种子）；来访与世界事实的一致性约束；
现有 tick（日粒度）与窗口结算的关系：**tick 管世界的一天，窗口结算管院子的时段**，
同源不冲突，具体实现方案实施时定。
### Director
D1 欢迎结算（一次性）；结果节奏保障（§六 供给面顺序，禁硬造）；来访稀疏度守门。
### 数值
全归 22：窗口粒度 / 每窗来访数 / trace_only 比例 / 更换成本 / 首发物件与槽位数。
### API / Action
摆放 / 更换 / 收下；查询即结算（幂等）；**无召唤类接口**。
### Web / UI
院子实景槽位（非格子 UI，对应 11 母场景分层）；撞见态呈现；
发现流逐件（08 冻结：不做一键收菜）。
### 埋点
摆放 / 更换 / 窗口结算 / 发现 / 收下 / observedLive；
D1/D2 完成旗标的事件落点（旗标定义归 20）。
### 文案 / 美术 / 音频
行为与痕迹表达过 04（环境语言）与 11（Home Yard 分层）；
"安静的窗口"的表达（休刊日精神）。
### 旧规则迁移
既有三时段浮现 KEEP（升级为窗口浮现面）；"叼回小东西约 3-5 天一件"
MIGRATE→leftBehind 节奏（22 重校）；旧 D1 相遇剧本（doc/21 七拍）与 /adopt
链路处置**另案**——D0 尾部承接归 14 迭代，全链路清扫在批次三 14/15 议。
### 验证指标
D1_COMPLETE 达成率与达成时长；首 session 内完成首个"摆→等→发现"闭环的比例；
回访-发现命中率（每次回访有发现物的比例，应接近全命中）；
撞见率（observedLive 占比，观察项不设目标）；悬念盲读通过率（§九）。
