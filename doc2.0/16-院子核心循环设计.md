## 零、核心论点：循环的本体是两个时钟的咬合（第一性原理，冻结）

- **世界钟**：worldDay × Visit Window——事实在这里发生；
- **用户钟**：session（开门→发现→调整→离开，08 七拍）——发现在这里发生。

玩法 = 用户在自己的时刻，收世界在自己的时刻产生的结果。
两个钟永不同步，**这个错位就是等待的形状、悬念的来源**（08 §三）。
一切设计围绕保护这个错位：不搞实时喂养，也不搞"打开才发生"。

三条与此同级冻结的底线：**摆放不重写已发生的世界 · 刷新不重 roll ·
来访必须是世界模拟中的合法事实。**

## 一、放什么：物件（六问之 1）

- 物件 = 院子里的实物，三重属性：**标签**（偏好匹配面，体系归 17）、
  **状态**（新旧、使用痕迹——可被发现，08 拍 2）、**位置适配**（哪些槽位放得下）；
- 获取与维护归 19（维护用世界语言："用旧了""该打理了"，永不 HP 条）；
  首发清单与成本归 22；
- 语言红线：用户侧永远是"**摆了什么**"，不是"用什么召唤/吸引"（04）——
  物件是生活布置，不是诱饵道具。

## 二、放哪里：槽位与位置差异（六问之 2）

- 院子 = 一张实景（11 Home Yard 母场景），槽位 = 场景里的**具体位置**
  （屋檐下 / 老树旁 / 空地 / 门口台阶……），不是抽象格子；
- 每个槽位自带位置属性（遮蔽/日照/高低/离门远近……标签体系归 17）——
  **同一物件放不同位置 = 不同实验**，这是"研究"环的空间维度；
- 槽位数量有限是设计：限制才产生选择；初始数量与扩槽节奏归 19/22；
- 动作三个（08 冻结）：摆放 / 更换 / 收下；更换成本参数归 22，
  冷却不默认存在（08 冻结注记）。

## 三、时间结构：叙事时段与来访窗口解耦（六问之 3，本篇最重要修订）

```
World Day
├── Narrative Segment：上午
│      ├── Visit Window
│      ├── Visit Window
│      └── …
├── Narrative Segment：下午
│      └── …
└── Narrative Segment：晚上
       └── …
```

- **Narrative Segment**（上午/下午/晚上，既有三时段 KEEP）负责
  "**这个世界现在是什么时候**"——叙事口径、内容浮现、世界的表盘；
- **Visit Window** 负责"**院子里的实验什么时候有机会得到答案**"——
  玩法结算的原子单位；
- 结构红线：**Visit Window 粒度必须显著小于 Narrative Segment**；
  多个 Window 归属同一 Segment；具体时长归 22。
  叙事只说"下午"，后台在这个下午里已经发生过多次来访判定——
  实验反馈速度是这个游戏的命，不能被叙事时段拖成一天两三次；
- **生效规则**：摆下即生效于**下一个尚未开始的 Visit Window**；
  当前窗口内的生活不重排——世界不为你重演（07 结果权的时间形态）；
- **等待的三种自然长度**——不是三种机制，是同一时间轴上的三种距离：
  窗口内（撞见此刻在场的猫）／下一个 Visit Window（常规实验的等待）／
  跨 Segment 或跨日（条件类：时段专属、天气、稀有组合）；
- **D1 阶段特例（欢迎结算，一次性）**：第一次摆放触发一次加速结算，
  保证 D1_COMPLETE 可在首个 session 内达成。**欢迎结算不破坏正式规则**：
  它保证的是"在合法候选中产生结果"，不是"绕过条件指定结果"——
  用户放纸箱，第一只来的猫也必须是纸箱条件下合法的猫。
  仅 D1 阶段一次，永不成为常态机制；
- 离线不暂停：窗口照常结算，结果与痕迹累积，不过期（08 §三）。

## 四、世界如何产生 CatVisit（六问之 4）

- **来访是世界模拟中的合法事实**（08 冻结口径）：实现形态不预设——
  location state / schedule / transition 皆可，唯一硬约束是**一致性**：
  同一只猫的行踪在世界叙事与院子事实之间不得自相矛盾。
  世界猫实例问题按 README §九·1 处理（21 拍板，拍板前从严）；
- **生成时机与确定性**：窗口开始时（或窗口开始后首次被查询时）结算。
  **确定性种子（yardId × worldDay × windowIndex）**——查询多少次结果都一样，
  **刷新永不重 roll**（红线，CI 级校验）；
- **快照红线（Lazy settlement 可以晚算，绝不能晚取事实输入）**：

```
WindowFact = f(
  deterministicSeed,                      // yardId × worldDay × windowIndex
  placementSnapshotAtWindowStart,         // 窗口起点的布置快照，非查询时现状
  worldStateSnapshot                      // 天气/时段/社会状态同理取窗口起点
)
```

  窗口开始后用户换了物件、系统才被首次查询——结算仍必须按窗口起点的快照算，
  **历史永不被未来改写**；
- **输入接口**（公式与权重全部归 17）：
  布置快照 × 猫的偏好与状态 × 时间 × 天气 × 院子状态 × 社会状态 → 来访倾向；
- **来访保持稀疏**：允许空窗口，单窗口只出现少量猫（精确数归 22）——
  天天满院，猫就成了刷新物（L2 反例）；
- 无来访是合法结算结果，且窗口仍可产生非来访发现物（§六）。

## 五、事实、暴露与观察：三层分离（六问之 4 续，数据模型冻结）

**CatVisit 是完整世界事实——世界永远知道全部**；用户知道多少是另一层。
（与既有"客观事实 DB × 主观认知"双层记忆哲学同构：世界知道发生了什么，
用户不一定知道发生了什么。）

```
CatVisit {                    // 完整世界事实（永不残缺）
  id, catId, yardId,
  window: worldDay × windowIndex,   // 叙事引用时映射到所属 Segment
  slotId?, itemId?,                 // 它用了哪儿、用了什么（可空：只是路过）
  arriveAt, leaveAt,
  behaviors[],                      // 行为（池与生成归 17/10；必须允许无用行为）
  leftBehind[],                     // 留下的：小鱼干 / 纪念物（数值归 19/22）
  traces[],                         // 痕迹（表达归 04 环境语言、11）
}

VisitDisclosure {             // 暴露完整度：用户"被允许知道多少"
  visitId, yardId,
  visibility: LIVE | FULL_RECORD | TRACE_ONLY | HIDDEN
}

Observation {                 // 观察事实：谁、何时、以什么方式看到
  viewerId, visitId,
  type: LIVE | TRACE | RECORD | PHOTO,
  observedAt
}
```

- **trace_only 保留为体验设计，但它是暴露度不是事实残缺**——猫社会、世界履历、
  兴趣组目击、Trace 溯源都依赖事实层无缺口；
- **观察不改变世界事实**：开门只产生 Observation，永不触发结算改写——
  "刷新不重 roll"因此更干净；
- **观察不产生额外收益**（原 observedLive 原则的归位）：LIVE 型观察与事后发现
  的收益完全一致——否则等待会退化成蹲守；
- MVP 实现可折叠（如 Disclosure 并入 CatVisit 存储、Observation 只记首次），
  但**概念模型不许折叠**——语义分层是 21 社会化的地基，现在混了将来必迁移；
- 红线：不许用 TRACE_ONLY 掩盖"没有内容"——痕迹也是内容，同样过 04 表达关。

## 六、用户什么时候看到结果（六问之 5）

- 已结算窗口中被 Disclosure 允许的部分，开门即可见——不做逐条解锁的动画排队；
- 进行中的窗口：此刻在场的猫可被撞见（LIVE 观察，无收益差）；
- 结果六类（README）：看到当前猫 / 来过的痕迹 / 新猫解锁（岛猫册，归 18）/
  资源 / 新行为 / 猫之间互动；
- **结果节奏保障（08 冻结口径的系统化）**：每次回访至少一件可发现的事，
  且**可发现 ≠ 来访**。发现分两族：

  **Yard Discovery**（我的院子真的发生了什么）：来访 → 旧痕迹的变化 →
  物件状态 → 环境变化（天气/时段痕迹）；
  **World Discovery**（岛上别处发生了什么）：岛闻。

  供给规则：Yard 族优先；**World Discovery 可以补充体验，但不能永久代偿
  Yard Discovery 的长期贫瘠**——院子长期没东西可发现是模拟器/供给的病，
  岛闻不许当遮羞布（eval §九 代偿审计）。
  **Director 永不为凑节奏硬造 CatVisit**；真的安静时，"今天很安静"本身
  要被可感知地表达（休刊日精神：安静也是质感）；
- 收下（08 拍 4）：逐件发现式，不做一键收菜；不腐烂、不过期。

## 七、一次结果如何转化成下一次期待（六问之 6）

**session 级原则（评审修订）：每个有效 session 应有机会自然留下至少一个开放端；
不是每一个结果都必须承担目标。**

```
一次 session
├─ 猫 A 打哈欠         ← 可以什么用都没有（L3 无用层，08"看日子的忙"）
├─ 猫 B 喝水           ← 可以只是好看
├─ 新猫第一次出现       ← 收集开放端
└─ 纸箱被重复使用       ← 研究开放端
```

内容不全是钩子——**所有内容都在服务 Retention 的世界，生命感必死**。

开放端的四类来源（是材料，不是任务——08：只提供材料，不派目标）：

1. **行为即线索**："它在纸箱里待了很久" → 暗示偏好。线索信息量归 17 校准：
   **能学，但一次学不完**（规律是主体，随机负责惊喜）；
2. **岛猫册的未知槽与未补全观察**（18）：看见即目标感，永不倒计时；
3. **新物件的可能性**（19）：资源攒到某处，自然想到"换了它能试什么"；
4. **岛闻线索**（01/03 管线）：别处的猫的说法 → "会不会来我这儿"。

红线：开放端永不写成任务句——"试试把纸箱放到屋檐下"这类句式禁
（攻略腔不是世界；04 词典）。

**总验收（评审修订）：离开时，用户心里存在至少一个自己产生的未完成问题。**
典型形态：下一次会来谁？／怎么让那只再来？／换这个物件会怎样？／
这个规律是不是真的？／还差多少能试新的东西？／那两只为什么总一起出现？

**D1 专属验收**保留原句：**"我换个东西，下一次会来谁？"**

## 八、状态机（系统侧）

```
布置态 ──摆放/更换──▶ 生效等待（下一个 Visit Window 起点）
窗口起点 ──固化 Placement/World 快照──▶ 世界结算（确定性种子）
        ──▶ 窗口事实（CatVisit[] + 发现物）＋ Disclosure 判定
现实时间过窗 ──▶ 可发现（开门产生 Observation；在场可撞见 LIVE）
用户开门 ──发现/收下──▶ 回到布置态
（离线：窗口照常结算，结果累积，不过期）
（D1 特例：首摆 → 欢迎结算，一次性，合法候选内产生结果）
```

红线汇总：刷新不重 roll（确定性种子）· **晚算不晚取**（窗口起点快照）·
摆放只影响未开始的窗口 · 观察不改变世界事实 · 观察无收益差 ·
无召唤类机制 · 冷却不默认存在 · 来访必须是世界合法事实 ·
结果节奏不硬造来访 · 岛闻不代偿院子贫瘠 · 欢迎结算不绕条件。

## 九、eval

- **确定性抽检**（CI 级）：同窗口重复查询，结果逐字段一致；
- **快照抽检**（CI 级）：窗口开始后更换物件再触发 lazy settlement，
  结果必须与按窗口起点快照计算一致——历史不被未来改写；
- **一致性抽检**：抽任一 CatVisit，该猫同窗口的世界叙事无矛盾
  （日报说它在渔港、它却在你院子 = 缺陷；21 拍板实例规则前从严）；
- **时间轴抽检**：摆放生效于下一个 Visit Window，当前窗口不受影响；
- **结果节奏抽检**：连续多次回访零发现 = 缺陷；
  来访率随回访频率上升 = **P0**（硬造来访的证据）；
- **代偿审计**：岛闻（World Discovery）在发现供给中的占比监控——
  长期高占比报警 = Yard Discovery 贫瘠被掩盖；
- **观察无收益差审计**：LIVE 观察与事后发现的产出完全一致（防蹲守）；
- **悬念盲读**（定性，session 级）：抽 session 结尾，能否指出
  "这个用户下一次想试什么"——指不出 = 开放端供给失败。

## 合回清单

### 数据模型
Yard / YardSlot（位置属性）/ Placement（含生效窗口 + **窗口起点快照**）/
**CatVisit（纯世界事实）** / **VisitDisclosure** / **Observation**
（MVP 可折叠实现，语义不折叠）/ 发现物与收取状态。
### Simulation
Visit Window 结算管线（确定性种子 + 快照输入）；Narrative Segment 与
Visit Window 的归属映射（叙事引用时段，玩法引用窗口）；
tick 关系：**tick 管世界的一天，Narrative Segment 管叙事的时刻，
Visit Window 管院子的实验节拍**——同源不冲突，实现方案实施时定；
来访与世界事实的一致性约束。
### Director
D1 欢迎结算（一次性，合法候选内产生结果）；结果节奏保障
（§六 两族供给 + 禁硬造 + 岛闻不代偿）；来访稀疏度守门（定性）。
### 数值
全归 22：每 Segment 的 Window 数与时长 / 每窗来访量 / TRACE_ONLY 比例 /
更换成本 / 首发物件与槽位数。
### API / Action
摆放 / 更换 / 收下；查询即结算（幂等，按快照）；**无召唤类接口**。
### Web / UI
院子实景槽位（非格子 UI，对应 11 母场景分层）；撞见态呈现；
发现流逐件（08 冻结：不做一键收菜）。
### 埋点
摆放 / 更换 / 窗口结算 / Observation（LIVE/TRACE/RECORD 分型）/ 收下；
D1/D2 完成旗标的事件落点（旗标定义归 20）。
### 文案 / 美术 / 音频
行为与痕迹表达过 04（环境语言）与 11（Home Yard 分层）；
"安静的窗口"的表达（休刊日精神）。
### 旧规则迁移
既有三时段 KEEP（升级为 Narrative Segment，卸下玩法 Tick 职责）；
既有时段浮现 KEEP（叙事浮现面）；"叼回小东西约 3-5 天一件"
MIGRATE→leftBehind 节奏（22 重校）；旧 D1 相遇剧本（doc/21 七拍）与 /adopt
链路处置**另案**——D0 尾部承接归 14 迭代，全链路清扫在批次三 14/15 议。
### 验证指标
D1_COMPLETE 达成率与达成时长；首 session 内完成首个"摆→等→发现"闭环的比例；
回访-发现命中率（应接近全命中，且分族统计 Yard/World 占比）；
撞见率（LIVE 观察占比，观察项不设目标）；悬念盲读通过率（§九）。
