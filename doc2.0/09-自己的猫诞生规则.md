# doc2.0/09 自己的猫诞生规则——什么时候，一只猫成为"你的猫"

> 2026-08-05 立稿（评审指定）。命题（创始人）：七仔是入口，但用户最终需要
> "属于我的生命"。必须避免传统领养——**不是选择一只猫，而是一段关系自然形成**。
> 核心问题：什么时候一只猫成为"你的猫"？
>
> 答案：**系统从不宣布；岛慢慢开始这么称呼。**
>
> 与 doc/21（D1 相遇剧本 v2，主线已拍板）的关系：doc/21 管"相遇"那一天，
> 本文管"成为"那一个月——**不推翻 D1，是给 D1 之后的归属一个诞生过程**。
> （设计取舍说明见 §八：为什么不做"完全涌现式"。）

## 零、核心论点："你的猫"是一个称呼的诞生，不是一个按钮的结果

- 传统领养：点击 → 系统宣布 → 获得所有权；
- 猫岛：**相遇 → 相认 → 落笔**——所有权从不被宣布，归属被岛承认。

它先是它自己，然后才是你的猫（05 身份层：名字与来历在先，归属在后）。

## 一、诞生三段

| 段 | 时间 | 发生什么 | 机制 |
| --- | --- | --- | --- |
| **相遇** | D1 | 你们互相撞见；它拒绝过你、又送你一件它本想留下的东西；你留下第一句话 | doc/21 七拍（原样不动） |
| **相认** | D2–D30 | 它用行为认你（§二）；你用回来认它 | doc/07 四阶段 + 记忆复利 |
| **落笔** | 约 D7–D30 间的某天 | **老章在岛民册它那一行，写下你的名字** | 本文新增（§三） |

事实层说明（诚实处理）：数据绑定仍在 D1 发生——海螺、日记、留言的归属需要它，
D1 漏斗判据（adopt_complete ≥60%）不变。但**绑定是世界的私事，
永不以"领养成功"的形式出现**——产品语言里只有"遇见"（doc/21 定位口径既有拍板）。

## 二、相认：它的四种认你方式（全部是行为，全部有既有机制）

1. **它在你常来的时候出现在门口**——用户偏好时段被动学习（doc/19 已实现）；
   "它在等你"只能是岛民的说法（心事归旁人，doc/21 拟人化红线）；
2. **它记得你的说话方式**——留言消化、跨周引用、它对你的称呼（doc/07 D2 起）；
3. **它把捡到的东西带给你**——叼回小东西：从 D1 的"割舍"到日常的"惦记"
   （doc/21 §五 原文）；
4. **它开始问你问题**——D4 起第一次主动问主人（doc/07）。

呈现红线：四种方式**只演出，永不解释**——"它已经把你当主人了"这类句子
禁止出现（04 沉默声部）。

## 三、落笔：岛的承认（本文核心新增）

- 老章记性极好、落笔认真（NPC 既有设定）——**他只在"看得出来了"的时候才落笔**；
- **触发判据 = 关系事实的确定性累积**（方向示例：首周走完 + 它送过你东西 +
  你回来过若干天 + 它记住过你的话）。阈值隐藏、永不显示进度；
  **判据看"发生过"，不看"连续"——不惩罚缺席**（半个月来一次的岛民，
  也能等到自己的落笔）；
- **落笔不通知**：某天你翻开岛民册，它那一行的主人栏里有了你的名字——
  **是被发现的，不是被推送的**。发现之后，可以有一封海螺跟进
  （进"第一次"系列：第一次落笔）；
- **落笔日 ≠ 相遇日**：它成为你的猫的日子，比你遇见它的日子晚——这是对的，
  关系本来就比相遇晚；
- 与第七行同构：七仔的主人栏被划掉过很多次——**在这个世界里，落笔是重的**。
  这正是它值得被等的原因。

## 四、社会称呼的跟随（03 管线复用，非 MVP 阻塞）

落笔之后，岛的语言慢慢跟上：岛民口中出现"你家那只""小灰的主人"（隐私门内），
日报在并称之前会先自然使用所属称呼。顺序守 03 铁律——**恒慢半拍**：
岛上这么说，必然晚于老章落笔；老章落笔，必然晚于它自己认你。

## 五、速度与红线

- **落笔不早于 D7**（首周是相认，不是归属）；上不封顶（判据看事实不看打卡）；
- 永不出现：领养成功 / 绑定完成 / 解锁 / 恭喜获得（04 词典，领养语系全禁）；
- **永不显示落笔进度**（"还差 2 项成为你的猫" = P0）；
- **落笔是意义事件，不是权限门**：未落笔期间产品功能无差别
  （海螺/日记/留言/摸摸它照常）——落笔改变的是称呼，不是能力；
- 它先是它自己：落笔之后，它依然会拒绝你（07 结果权不变）。

## 六、eval

- **落笔可追溯**：任一落笔时刻能从事件史指认"为什么是这一天"——
  指不出 = 系统在发糖，判缺陷；
- **语言扫描**："领养成功"语系出现即 P0；
- **时序抽检**：落笔 ≥ D7；社会称呼晚于落笔；
- **定性北极星**：用户描述那一刻用的词——是"我领养了它"，
  还是**"它成了我的猫"**。

## 七、合回清单

- 岛民册页面：你的猫那一行的主人栏（空 → 手写体名字）+ 被发现态；
- 落笔判据函数（事实派生、阈值隐藏）+ "第一次落笔"进第一次系列与海螺选稿池；
- adopt 流程全部文案过"永不宣布"审计（配 04 语言门）；
- doc/21 加指针（相遇 → 成为的分工）；
- §四 社会称呼依赖 03 合回——**MVP 只落"老章落笔"单点**，称呼跟随后置。

## 八、设计取舍存档：为什么不做"完全涌现式"

激进方案曾被考虑：D1 不确定对象，用户与多只猫接触，其中一只随时间
"自然长成"你的猫。未采用，理由：

1. 召回机器（海螺绑定/首周曲线/资产管线）全部依赖 D1 有确定对象——
   涌现式会拆掉 D2 兑现这条最强的回访链；
2. doc/21 的"遇见"设计已消灭"挑选宠物"感——相遇的确定性不等于领养的宣布感；
3. 涌现式把归属交给随机漂移，用户无法向朋友讲"我们怎么开始的"——
   而"怎么开始的"是四件私人资产之首。

本文取"**相遇即时、归属渐进、承认在岛**"三段式：情绪价值全保留，工程链路零破坏。
