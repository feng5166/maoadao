## 零、核心论点：舍不得走 = 攒下了带不走的东西

留存的终极形态不是"明天还来"，是"这里有只属于我的、不可迁移的东西"：
你的猫的记忆、你起的名字在岛上流通、你的猫和别的猫的关系史、岛民册上你那一行。

**关系资产不可复制、不可购买、不可加速——只能靠时间生活出来。**
内容可以被竞品模仿，共同生活史不能。这是 maoadao 的长期护城河。

评审补注（2026-08-05）：本文还回答了"为什么用户愿意拥有自己的猫"——
你的猫不是系统分配，是**关系自然形成**。doc/21 的 D1 相遇设计
（撞见/拒绝/它送你东西）正是这条哲学压缩进第一天的版本。

## 一、关系的三种货币（替代亲密度）

关系不用数值计价，用三种**可指认**的东西计价：

| 货币 | 是什么 | 落库形态 |
| --- | --- | --- |
| 事件 | 一起经历过的事（"因为那件事"） | SimulationEvent〔已运转〕 |
| 习惯 | 重复出现、只属于这两只的相处方式 | 双猫共同事件派生统计〔增量〕 |
| 记忆物 | 共同记忆的物证 | MemoryEntry keepsake/relation，扩 pair 维度〔增量〕 |

模拟器内部照旧维护关系值做裁决（唯一事实来源，doc/00 §五）——但那是世界的私事。
**产品侧任何地方出现关系数值/等级/进度条，即 P0**（用户侧禁裸数值，doc/05）。

数据模型拍板（2026-08-05 评审）：三货币即底层模型——存 `shared_events[]` /
`shared_habits[]`（派生）/ `memory_objects[]`，**不存 `friendship=85`**。
模拟器裁决所需的关系强度**降级为派生缓存**：由共同事件史重放推导
（doc/09 §六 思路），事实源头永远是事件。

## 二、猫如何成为朋友（事件的积累）

关系阶梯（自然语言四段，与 doc/07 主人四阶段同构）：

```
见过 →(一件共同经历的事)→ 熟了 →(专属习惯出现)→ 有默契 →(记忆物+岛上并称)→ 老朋友
```

阶梯是**状态描述，不是等级**（禁 Lv、禁进度、"老朋友"永不量化）。四段的体感：

- 见过——"哦，是那只猫。"
- 熟了——"它知道你是谁。"
- 有默契——"它知道你会怎么做。"
- 老朋友——**"别人不知道，但你们知道。"**

五条规则：

1. **朋友的判据：能说出"因为那件事"。** 任何友谊必须可追溯到一个落库事件。
   "它们是朋友，因为风筝线那天"成立；"因为好感度 85"永不成立。
2. **推进单位是共同经历，不是互动次数。** 十次擦肩不如一次一起躲雨——
   习俗层（01 §三 雨天/大退潮日）天然是共同经历的高发场，两文在此咬合。
3. **允许不对称。** 小橘把七仔当最好的朋友，七仔对谁都一样好——这不是 bug，
   是角色（doc/22 红线④）。单方面的深情允许且可叙事。
4. **允许合不来与闹别扭。** 低强度冲突 → 各自别扭 → 修复；**修复事件比初识事件
   更长关系**（吵过架的才是老朋友）。冲突是轻喜剧，不是狗血（doc/07 D5 原则）。
5. **友谊长得慢（速度红线，2026-08-05 评审加严）。** 第一周最多"见过→熟了"；
   第一月才可能"熟了→有默契"；"老朋友"以**数月**计。
   慢造就稀缺——AI 若能一天模拟十年友情，用户反而不会珍惜
   （与"无用即有用"同一套逻辑）。**任何加速关系的设计（送礼刷好感）永不做**。

## 三、猫如何产生默契（关系的可见形态）

默契定义：**重复出现、且只属于这两只猫的相处方式。**

四种形态（从生活里涌现，不预设剧本）：

- **固定的碰面**：每天傍晚都在码头东头，谁也没约谁；
- **专属的招呼**：别的猫碰鼻子，它们俩是尾巴搭一下；
- **只有它们的分工**：一只翻，一只守着看；
- **互相留东西的位置**：七仔木箱边那块石头，小橘的东西总放在那儿。

机制：**零新模拟机制**——双猫共同事件的地点/时段/类型统计（doc/09 §六
派生思路同款）涌现出模式，叙事层把统计翻译成默契〔增量：统计加双猫维度〕。

呈现红线：**默契只演出，永不解释。** 禁写"它们很有默契"；
只写"它们同时到了码头。谁也没说什么。"**专属称呼是默契的最高形态**（"那边/这边"）。

## 四、猫如何留下共同记忆（关系的物证）

- 够深的关系会留下一件**物**：一起找到的、一起修好的、分成两半各留一半的；
- 记忆物走既有链路：MemoryEntry → 日记素材 → 小屋收藏（P3）→ 分享卡；
- **沉淀，不是刷新**（评审样例）：普通产品——"今天它捡到贝壳"；猫岛——
  三个月后贝壳还在屋里，旁边多了一颗松果。用户："原来它一直留着。"
  这一刻是 01（生活）与 02（关系）之间的桥；
- **回响规则**：数周后的日记允许引用共同记忆（"上次和小橘来的时候，
  这里还没长草"）——记忆复利从"猫记得你"扩展为**"猫互相记得"**
  〔增量：记忆检索加关系维度〕；
- **并称**：老朋友会被岛的语言承认——岛闻/日报开始并称（"码头那两只"）。
  **社会承认是关系的最终形态**，也是用户一眼能看出"它们是老朋友"的方式。
  （评审：方向通过，**生成规则未冻结**——永不系统颁发称号，只能从旁人语言里
  自然长出："你又和那两个家伙一起去了码头？"完整机制 → doc2.0/03。）

## 五、用户如何从观察者变成岛上的一员

一员的定义：**被这个世界记得，而不是能操纵这个世界。**
（"一双手"——用户动手做什么——是 03 的议题；本节只回答"被记得"。）

三层递进：

1. **你的猫记得你**〔已运转〕：主人关系四阶段（doc/07）、记忆复利、
   跨周引用、它对你的称呼。
2. **你的痕迹进入岛的语言**〔已运转 + 低成本增量〕：
   - 你起的名字在岛上流通：物件命名后，日记与岛闻用你起的名字复述
     （"它把那枚『星期三』又擦了一遍"）——**你的词汇进入了岛的词典**；
   - 你留下的东西可能被七仔捡走（被捡走机制，公共通道）；
   - 你说的话经转译流进它的世界（doc/23 §二，私有通道）。
3. **岛知道有你这个人**〔长线，克制〕：登记处老猫的岛民册记着你哪天登的岛
   （NPC bio 既有设定："谁哪天登的岛，他都记得"）；你的猫的朋友从它嘴里
   听说过你（交叉视角扩展，**提及主人必须过隐私门**：仅 visibility=public
   的内容）〔增量〕。
   红线：**NPC 永不直接与用户建立关系**——一切经由你的猫。
   岛记得你，但只有你的猫认识你（doc/22 红线④的镜像）。

总口径（评审补）：**岛对你的认知永远是二手的**——一切经由你的猫流出、过隐私门。
样例：你说"今天下雨，好烦" → 它记下（主人记忆）→ 某个雨天它的日记想起你嫌烦的雨
→ 它的朋友从它那儿听说"它的主人不喜欢雨"。
**世界记住玩家，而不是玩家改变世界**——这是猫岛与普通游戏的身份分界。

## 六、验收（eval 接口）

- **关系抽检**：任取一对"朋友"，能否从事件史指出"因为那件事"——指不出=数据造假；
- **文案抽检**：出现好感/亲密度/等级/进度即 P0；"它们很有默契"这类解释句即缺陷；
- **速度抽检**（按加严红线）：干跑 30 天内不得出现"老朋友"（数月计）；
  "有默契"不得早于第 4 周；
- **回响抽检**：老朋友日记里的共同记忆引用，必须能指认出处事件。

## 九、2.1 玩法化接口：它认得你这个人（2026-08-08 增量立稿，待评审）

> 命题（创始人点题）：**院子熟悉是"它认得这个地方"，居民关系是"它认得你这个人"。**
> 只解决三件事，不重写关系哲学；三货币/四段阶梯/速度红线全部照旧生效。

### 9.1 两个"熟"的正式分离（三件事之①，冻结候选）

```
CatHomeAffinity          它认得这个地方 —— 05 §十 持有
├─ 来源：HomeHistory（它在这个院子真实生活过的一切）
├─ 出口：Visit Preference 的有界修饰（0～+0.5，防常客锁死三红线）
└─ 与"谁是院子的主人"无关——它爱的可以只是那只旧水盆

CatUserRelationship      它认得你这个人 —— 本章持有
├─ 来源：InteractionFact（你和它双方都在场的真实互动事实，9.2）
├─ 形态：三货币的用户版（共同经历 / 专属习惯 / 共同记忆），状态非等级
└─ 出口：行为与叙事 —— 不是概率
```

**分离红线（冻结候选）：**

- **常来 ≠ 跟你熟**——来访喂 HomeHistory，不自动喂关系；
  关系需要"和你"的共同经历，不是"在你院子"的活动记录；
- **两边永不互写**——affinity 不因关系好而涨，关系不因来访多而涨；
  各自从各自的事实层派生（CI：分离审计）；
- **关系的出口是行为与叙事，不是概率（冻结候选）**——关系好 ≠ 更常来
  （那是偏好与 affinity 的事）；关系好 = 来的时候对你不一样
  （它冲你那边多看一眼 / 把东西留在离门更近的地方 / 你的名字出现在老章的册子里）。
  CatUserRelationship 永不进入结算输入集（与 01 §九 Eligibility 禁读清单、
  05 §十 防常客锁死同族——**三条防线合起来：任何"熟"都买不到来访概率**）。

### 9.2 关系从哪来：真实互动事实（三件事之②，红线冻结候选）

```
用户动作（07：输入永远是事件，不是命令）
        ↓ 猫按自己的性格与当下状态真实回应 —— 可以不回应（拒绝合法）
InteractionFact（双方在场的事实：挂 visitId / eventId 溯源）
        ↓ 积累（速度红线照旧：老朋友以数月计）
CatUserRelationship（三货币用户版，派生态）
```

> **红线（创始人拍板）：用户动作本身不直接加关系；
> 只有猫真实经历并产生可观察回应，关系才成立。**

- "摸摸它 +2 好感"这类路径**永远不存在**（05 §十 防好感度化的关系版）；
- 合法路径只有一条：你做了一件事 → 它**真的**经历了并给出回应
  （蹭了你 / 躲开了 / 装没看见）→ 这个回应作为事实落档 → 关系从事实派生；
- **拒绝也是回应**——躲开是它性格的表达，落 InteractionFact 但不产生"负分"
  （关系没有分数）；无回应（它根本没注意到）不落任何事实，且不补偿；
- 动作清单本章不定（"摸摸它/留一句话"的去留随 Yard 呈现格实施时裁决，
  物件命名倾向保留承 README §九·3）——本章只定管线：
  **凡关系动作，必须走"动作→真实回应→事实→派生"，无一例外。**

### 9.3 落笔与命名→回应：降级为关系深化资产（三件事之③，冻结候选）

v1《自己的猫诞生规则》的"相认（四种认你方式）→ 落笔（老章写下你的名字）"
不再承担主循环入口——2.1 的主循环是院子实验（16），不是单猫聚焦。处置：

- **机制未死，降级归档**：落笔成为关系阶梯**后段**（熟 → 朋友）的存档设计——
  当 InteractionFact 积累到关系成立（判据归 22，不是计数阈值），
  老章的册子上才会出现那一笔。不通知、被发现、可追溯、不惩罚缺席、
  对外不承诺时限——五条原则原样继承；
- **命名 → 回应**保留为关系动作的一种：它认不认你起的名字，本身就是
  9.2 管线里的一个回应事实（认了=专属习惯的开端；不认=还没到时候）；
- 实施后置：本章冻结只锁语义与红线，落笔的工程实现待关系管线落地后另案
  （不进当前实施主线清单）。

### 9.4 eval（增量）

- **好感度化审计（CI 级）**：出现"用户动作 → CatUserRelationship 直接映射"
  的代码路径 = 缺陷（与 05 §十 affinity 审计成对）；
- **关系-概率隔离审计（CI 级）**：结算/Eligibility/Preference 的输入集出现
  CatUserRelationship = 缺陷；
- **分离审计**：affinity 与 relationship 之间存在任何读写边 = 缺陷；
- **拒绝合法抽检**：存在"动作被拒绝/被无视"且系统不找补（无安慰奖、无补偿概率）；
- **溯源审计**：任一 InteractionFact 指认 visitId/eventId，指不出 = 数据造假（05/06 同族）。

### 9.5 合回清单（增量）

数据模型：`InteractionFact`（id / catId / userId / kind / response /
sourceVisitId? / sourceEventId? / createdAt，append-only）；
`CatUserRelationship` 为派生态（可缓存可重算，永不手写）。
Simulation：回应生成挂猫的性格与当下状态（05）；关系派生函数（只读组合）。
Director：零写权（关系只由事实产生）。
数值：关系成立判据 / 各动作回应分布 → 22。
API / Action：关系动作接口随 Yard 呈现格实施（动作清单彼时裁决）。
Web / UI：关系呈现只走行为与叙事（永不出现关系条/数值/阶段标签）。
埋点：InteractionFact 即埋点事实，不另造。
旧规则迁移：v1 09 相认/落笔 MIGRATE→本章 9.3（归档语义）；
v1 五动作中"摸摸它/留一句话"KEEP 待裁（Yard 呈现格）；
禁词表照旧：好感、亲密度、默契值、关系等级。
