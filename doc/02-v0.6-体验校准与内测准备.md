# v0.6：体验校准与内测准备版

> 2026-07-30 拍板。v0.5 已完成核心循环闭环（用户身份→领养归属→跨日生活→干预→回执→沉淀→分享）。本版不做功能，做"让核心循环被真实用户稳定理解和使用"。

## 完成度判断（v0.5 时点）

已闭环：用户归属 / 跨日循环 / 世界连续性 / 干预反馈 / 内容生成 / 历史沉淀。基本闭环：分享回流、内容安全。已达小规模测试条件：工程稳定性。**仍偏弱：用户召回。未验证：情感牵挂、商业化。**

## 冻结清单（本阶段不做）

新事件线、更多 NPC、用户猫社交、地图扩张、商城、多猫、实时聊天、短视频、复杂经济、更多 Agent 自主规划——只会加复杂度，不回答关键问题。

## 三项 P0（进测试前必须）

1. **邮箱绑定与跨设备找回**：邮箱验证码登录、换设备找回、Cookie 丢失恢复、每日故事邮件（写成内容钩子而非系统通知："煤球今天打开了门口那把旧钥匙，但屋里并不是空的"）、可主动关闭。
2. **内部观察后台**：用户列表/猫/活跃/连续天数/日记/留言/建议采纳/事件线/审核结果/叙事失败/分享行为——否则种子测试只能看到留存数字，无法判断为什么流失。
3. **核心循环漏斗埋点**：landing_view → adopt_start → adopt_complete → first_story_view → first_intervention_submit → next_day_return → daily_story_view → intervention_submit → share_generate → share_open → referred_adopt_complete；带 cat/user/island_day/事件模板/人格/建议类型/是否采纳等维度。

## 首次体验校准

进入首页→理解产品→创建→看首日事件→明白猫会继续生活→完成首次干预→知道明天回来。首页与领养完成页必须反复表达：**"它会在你离开后继续生活。明天回来，它会告诉你发生了什么。"**

## 内容质量抽检（人工，每日）

抽：新用户首日、D3、D7、被分享、流失前最后一天、被拦截、低质内容。标：看得懂/体现人格/承接昨天/状态真变/有悬念/像不像模板/值得分享。

## 分层测试路径

1. 团队 Dogfood 5-10 人×7 天（找丢档/身份错乱/推进异常/叙事断裂/看不懂/移动端）
2. 熟人封闭 20-30 人×7-14 天（是否主动回来/记住 NPC/愿意留言/产生牵挂/第几天觉得重复）
3. 陌生种子 50-100 人（定位讲不讲得通/非熟人是否领养/内容能否传播）

## 三大产品风险

1. 用户是否理解猫是"持续生活"的（而非 AI 日记生成器）
2. 每日结果是否足以支撑等待（状态真变+建议被回应+剧情推进+新悬念，缺一不可）
3. 用户是否真的认领这只猫（领养日期/相处天数/见面纪念/专属称呼/共同记忆/周报纪念卡）

## 阶段目标

从"猫能不能自主生活"进入：**"用户愿不愿意把它当成自己的猫，并连续回来七天。"**
