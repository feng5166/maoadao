# 性能评审：页面打开慢的根因与分级方案

> **状态（2026-08-01）：P0-1 / P0-2 / P1-3 / P2-4 全部实施完毕。**
> 数据库已迁 Neon 新加坡（`ep-dawn-sunset-az6e8bd7`，ap-southeast-1，23 表全量核对迁移），
> 旧 us-east-1 库（neon-byzantium-button）已断开连接、保留作回滚备份，观察一周后可删。
> keep-warm cron 每 5 分钟已上线；各页查询已波次化；相遇照片缩略已加。

> 2026-08-01 评审。主诉：所有页面打开都太慢。
> 结论先行：**慢的根源不在前端，在"函数与数据库隔了一个太平洋"——
> hkg1 的函数逐条串行地查 us-east-1 的 Neon，每条查询付 ~215ms 往返。**

## 病灶定位（按贡献大小）

### 1. 跨洋数据库往返 × 串行查询数（主犯，占总耗时 70%+）

- 函数区域：`hkg1`（7-31 拍板迁来，为大陆首字节）
- 数据库：Neon `us-east-1`（`ep-quiet-frog-…us-east-1.aws.neon.tech`）
- 单次往返 ~210-230ms。页面查询序列实测（读代码计数）：

| 页面 | 串行往返数 | 仅 DB 耗时估算 |
| --- | --- | --- |
| /my-cat | **11-14**（Promise.all 只并了 4 条，其余 firstEvent→nudgeTotal→weekBook→viewer→echoHistory→arrivalNote→nudgeCount→todayEvents→targets→displayedDiary… 全是串行） | **2.4-3.0s** |
| /island | 4（world→viewerCat→all[4]→rels） | ~0.9s |
| / 首页 | 2 | ~0.45s |

### 2. Neon autosuspend：内测流量稀疏的隐形杀手

免费/默认档 5 分钟无查询即挂起，唤醒 500ms-2s。内测访问间隔远大于 5 分钟
→ **几乎每次真人访问都撞冷库**。叠加在 1 之上。

### 3. 连接建立开销

每个冷函数实例对 pgbouncer 做 TCP+TLS 握手（2-3 个往返）。跨洋时 ≈600ms；区域对齐后降到 ~10ms，此项自动消失。

### 4. 前端资产（次要）

- 相遇照片走 `/api/arrival-photo` 原图 ~1000px 无缩略参数（立绘 API 有 ?s=，照片没有）；`<img>` 无宽高 → 轻微 CLS
- 场景图/字体/analytics 均健康（系统字体零下载，scenes 走 next/image）

### 5. 域名异常（顺带发现，与"慢"无关但更严重）

从本机测点（代理出口）访问 apex `maoadao.com`：GET 返回的是**备案占位页 HTML（2112B）**，
HEAD 返回 **AliyunOSS 403（"bucket 不属于你"）**——与"占位站已拆"的认知冲突。
若部分真实用户也命中这条解析，体验不是慢，是根本没进站。**建议先人工确认当前主用域名的解析现状**（DNS 现状复杂，见 doc 备忘：apex 勿切回 Vercel 单 IP）。

## 分级方案

### P0-1：数据库迁 Neon 新加坡（ap-southeast-1）——一次配置，全站 5 倍

hkg1↔sin ≈ 35-40ms（对比现在 215ms）。/my-cat 仅 DB 从 ~2.6s → **~0.5s**，什么代码都不用改。
做法：Neon 新建 sin 项目 → `pg_dump | pg_restore`（数据量内测级，分钟内）→ 换两个 DATABASE_URL 环境变量 → 冒烟。
保留 hkg1 函数（大陆首字节收益不丢）。
备选对比过：函数迁回 iad1 与库同城（查询归零但大陆首字节 +250ms，放弃 7-31 的收益）——不如迁库。
**工作量：0.5 天内（含验证）。风险：迁移窗口短暂停写，选夜间。**

### P0-2：治 autosuspend

任选一：Neon 付费档拉长/关闭 autosuspend；或加一个 keep-warm cron（每 4 分钟 `SELECT 1` 的轻 API route + vercel.json cron）。
**工作量：30 分钟。**

### P1-3：查询合并——/my-cat 14 往返 → 3 波

- 无依赖的查询并成 2-3 个 `Promise.all` 波次（真正的依赖链只有 world.day→todayEvents、summary→displayedDiary）
- `getArrivalChecklist` 内部两查并行，nudgeCount 复用页面已查的
- world 表近乎只读 → 60s 模块级缓存
- 叠加 P0-1 后 /my-cat DB 时间 ~120ms。/island 同理 4→2 波。
**工作量：0.5 天（含跑通测试）。**

### P2-4：相遇照片缩略 + 尺寸属性

`/api/arrival-photo` 加 `?s=` 缩略（照抄立绘 API 的实现），页面 `<img>` 补 width/height。
**工作量：30 分钟。**

### P2-5：感知性能（P0/P1 落地后再评估是否还需要）

把 /my-cat 重查询下推进 Suspense 子组件，静态外壳先出、内容流式补。区域对齐后大概率不需要。
