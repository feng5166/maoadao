## 病灶（来自 30 天干跑）

1. **八卦逐字重复**：`templates.ts` 八卦池只有 4 条静态文案。「冰粉在攒钱开咖啡馆」30 天出现 7 次、「汤圆从来不干活」4 次——一字不差。
2. **后半月退化成借贷公告板**：灯塔线 D10 落幕后全岛只剩 debt 一种活跃事件线（D14-D30 新闻几乎全是借钱还钱），导演的「停滞线加权 ×3」还在给 debt 火上浇油。
3. **事件线事件占比仅约 3%**，而项目定义要求 30% 持续事件推进。中期（非首周）事件线只有 shop / debt / lighthouse 三种，其中：
   - **lighthouse 一次性**：`gossip` 入口判定 `!lighthouseExists`，全岛历史上开过一次就永不再触发；
   - **shop 实际从未开出**：条件 `coins > 75`，但干跑期末鱼币均值 44、最高 125——30 天 0 次开店。八卦里「黑豆筹备第八家店」成了与模拟现实矛盾的空头文案。
4. **rest 占 23.4% 且不可叙事**：最大事件类别产不出一句可看的内容。
5. **道具池撞车**：`FOUND_ITEMS` 里「一枚生锈的钥匙」高频出现，和首周主线纪念物「门口的旧钥匙」撞车，稀释纪念物的唯一感。

## P1：结构性修复（1-2 天）

1. **debt 泛滥治理**：
   - `borrow_money` 触发条件 `coins < 25` 收紧到 `< 15`，cooldownDays 3 → 5；
   - 导演停滞加权对**同 key 的多条线**只加权最老一条，且全岛同 key 活跃线 ≥3 时不再加权（防公告板效应）。
2. **shop 线降门槛**：开店成本 50 不变，触发条件 `coins > 75` → `> 55`；或加「合伙开店」变体（两只好感 >40 的猫凑钱，戏更多）。
3. **lighthouse 复用**：落幕 30 天后允许**另一只**高胆量猫重启（换主角换视角），或加一条 3 步「灯塔后续」短线（盐汽水的转变）。
4. **新中期事件线 2-3 条**（八卦里的伏笔已埋好，直接兑现，参照 lighthouse 的多步结构写 `threads.ts`）：
   - **冰粉的咖啡馆**（5-6 步）：攒钱 → 选址 → 找猫帮忙 → 试营业 → 按经营结果分支（爆火 / 第一天就翻车但大家来捧场）；
   - **汤圆之谜**（4 步）：为什么从不干活却顿顿有鱼——温情揭秘向（有猫一直在偷偷投喂）；
   - **将军的往事**（4 步）：风浪故事,老年剧情型,结构对标灯塔的「三十年留灯」情感钩子。
5. **同话题八卦冷却**：每条八卦挂 `topic` 字段，引擎选取时过滤全岛最近 5 天已出现过的 topic（WorldSnapshot 需带最近事实摘要，见 P2 动态八卦的前置）。

## P2：长期（验证 D7 后再做）

1. **动态八卦**：八卦内容从**最近 3 天真实事实**生成（谁吵架了、谁的店亏了、谁捡到怀表）——素材无限、永远为真、自带连续性，是「打听八卦」的终极形态。
2. **eval30 增加回归红线**：逐字重复台词计数、事件线事件占比（目标 ≥15%，远期 30%）、连续纯日常天数（≤2）、每周非 debt 事件线推进数（≥2）。把文档里的内容比例标准变成可跑的测试。

## 验收

改完后重跑 `npm run tick -- --dry` 干跑 30 天（可延长到 60 天）：

- 逐字重复台词：0 次；
- D10-D30 每周至少 2 条非 debt 事件线推进；
- 主事件连续两天同类型 <30% 的既有红线保持；
- shop 线 30 天内至少开出 1 家店；
- 抽读 3 只样本猫 D10-D25 流水，人工判断「耐看」。

## 明确不做

新 NPC 批量、新地图/地点系统、用户猫互动、把八卦改成 LLM 自由生成（违反事实先行架构）。
