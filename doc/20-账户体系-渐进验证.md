# doc/20 账户体系:邮箱密码登录 + 渐进验证

> 2026-08-04 拍板并当日实施 P0。
>
> **最终口径:船票让你第一次登岛;邮箱和密码让你以后能登录;回岛钥匙负责兜底;
> 当某项能力确实需要确认邮箱归属时,再请用户完成验证。**
>
> 核心取舍:注册即用(不打断 D1),验证是**能力升级门槛**而非使用门槛——
> 且不假装未验证的邮箱是一条可靠的回岛路。

## 一、凭证职责

| 凭证 | 作用 |
| --- | --- |
| 船票 | 首次登岛与领养资格 |
| 登录邮箱 | 唯一登录名(未验证时仅此而已) |
| 密码 | 登录认证(scrypt,见 lib/password.ts;NIST 风格策略:仅限最短 8 字符+常见密码拦截,允许中文/空格/Unicode,无组合规则) |
| 回岛钥匙 | 忘记密码的兜底(重置后旋转;验证邮箱后降为离线灾备,永不删除) |
| 海螺 | 猫与主人的连接通道,不参与账号认证 |

## 二、状态机

```
注册(邮箱+密码) → ACTIVE + emailVerifiedAt=null(UNVERIFIED) → 全功能可用
确认邮箱(验证码,复用 LoginCode 管线) → VERIFIED → 解锁:邮件找回/每日故事信/未来高价值能力
```

未验证不影响:养猫/跨设备邮箱密码登录/海螺/留言/船票/偏好。
页面口径:未验证显示"尚未确认归属",**不**称"回岛地址";验证后才叫"这条回岛地址已经确认"。

## 三、找回分层

- 未验证:登录=邮箱+密码;忘记密码=**只有回岛钥匙**(邮箱+钥匙双因子 → 设新密码 → 旧钥匙作废、新钥匙当场展示一次、不自动登录);
- 已验证:邮件重置为主,钥匙为备(邮件重置流程属 P1,未实施);
- 三样全丢:明确告知无法自动证明身份——不接受猫名/firstWords/日记描述作人工找回凭据(可被公开看到,不构成认证)。

## 四、冲突与安全规则(已实施)

- 邮箱唯一,未验证也占用登录名;占用时统一话术"无法使用这个邮箱",不暴露注册状态;
- 登录统一报错"邮箱或密码不正确",不区分不存在/密码错;
- 本设备已有另一只猫时登录 → 显式勾选确认切换,绝不静默合并;
- 限频:setup/login/recover 全走 AuthAttempt 滑动窗口;日志不落密码与完整钥匙;
- 退出登录仅对已设密码的身份展示(匿名身份退出即失联)。

## 五、验证的触发点(不弹窗追问)

1. 岛民册常驻低权重入口「确认邮箱」;
2. 能力触发:想开启邮件找回/每日故事信时;
3. (P1)D7 后生活册底部一次低权重提醒。

## 六、实施映射(P0,2026-08-04)

- `lib/password.ts`:scrypt(N=2^15,r=8,p=1)+ 策略;
- `lib/account-actions.ts`:setupCredentials / loginWithPassword / resetPasswordWithRecovery(钥匙旋转)/ logout;
- `/login` + `/login/reset`;首页未领养态入口"用邮箱和密码回来";
- 岛民册:「登录邮箱与密码」区(设置/状态/退出)+「确认邮箱」区(原绑定流程改口径,验证码管线复用);
- 身份卡三态:身份仅存于本设备 / 可邮箱登录·邮箱未确认 / 邮箱已确认;
- Resend key 已配(验证码邮件可发);User.passwordHash 已入库。

## 七、P1 落地(2026-08-04 接手补齐)

- **验证码不再能登录/接管账户**(§八 铁律):原 `verifyEmailCode` 是"邮箱+码=登录",
  有码无密码者可拿走别人的猫——已改为 `confirmEmailCode`,只把**当前登录账户自己的**
  邮箱标记为已确认,不碰任何身份;跨设备回岛一律邮箱+密码。
  同理 `recoverByCode`:已设密码的账户不再能用钥匙单独开门(那等于绕过密码),
  改走「忘记密码」的邮箱+钥匙双因子。
- **挑战锚定**:LoginCode 增 `purpose`(VERIFY_EMAIL|CHANGE_EMAIL|RESET_PASSWORD)+ `userId`
  (即 §七 EmailVerificationChallenge 的落地形态,沿用表名)。一码一用途、锚定账户,
  跨用途/跨账户兑换一律 invalid(tests/account-verify.test.ts 三例回归)。
- **修改登录邮箱**(§八 逃生舱):需当前密码;不验证旧邮箱;新邮箱唯一性走统一话术;
  替换后 `emailVerifiedAt=null` 回到未确认档。
- **修改密码**:需当前密码;回岛钥匙不动(离线灾备不因改密码作废)。
- **邮件重置密码**(§六 已验证档):只有"已确认 + 已设密码"的账户真的寄信,
  对外响应中性不暴露账户状态;重置成功不旋转钥匙(钥匙没被用到)。
  /login/reset 改为双路并列:上面邮箱路(注明需确认过),下面钥匙路。
- **验证后能力清单**(§五):岛民册列出已解锁的三条(邮件找回/每日故事信/多一条找到你的路)。
- **D7 低权重提醒**(§五 入口二):生活册末尾一句,只在 D7+ 且已设密码未确认时出现,不弹窗。

## 八、会话与钥匙(2026-08-04 补齐)

- **设备会话表**:cookie 里改放会话令牌(`maoadao_sid`,库存 sha256),`Session` 表记设备标签与
  最近活跃。**设过凭证的账户,uid cookie 单独不再算登录**——否则"踢出设备"形同虚设;
  匿名设备身份继续走 uid cookie(没凭证就没有踢出的意义)。岛民册可看在用设备、一键请其他设备下岛。
- **异常登录提醒**:账户已有别的设备在线 + 邮箱已确认归属 → 登录后 after() 里寄一封知会信,
  不挡登录路径。
- **钥匙不再裸奔**:页面只渲染脱敏串,完整串要调 action 现取;已设密码的账户取之前验一次密码。
  重置密码后当场给的新钥匙走 OneTimeKey(此刻不在登录态,无法验密码,只此一次)。
- **D1 存进岛民册**:/my-cat 在 D1-3 且未设凭证时就地给一次设置入口(刚见到猫是最愿意留凭证的时刻),
  设过即消失。
