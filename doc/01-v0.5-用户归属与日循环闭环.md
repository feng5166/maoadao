# v0.5：用户归属与日循环闭环版

> 2026-07-30 拍板。当前已有的是"世界模拟与内容生成后台"，缺的是三件基础能力：**用户身份、猫的归属、持续访问入口**。本版停止扩展"岛"，补齐"我的猫"。

## 最小核心循环

进入网站 → 创建或识别用户 → 领养一只猫并永久绑定 → 进入"我的猫"主页 → 查看猫今天的生活结果 → 留言或给出明日建议 → 系统推进一天 → 用户下次回来继续查看

日循环：查看结果 → 产生情绪 → 做一次干预 → 等待猫自主生活 → 回来看新结果

## 五个产品模块

1. **最轻量用户身份**：游客身份先行（匿名账户必须入库），登录用于找回（邮箱验证码 > 手机验证码 > 微信后续）。
2. **猫与用户永久绑定**：每用户一只猫；不能随意重置人格；可改名一次；外观生成失败不阻塞领养。无限重抽会毁掉归属感。
3. **/my-cat 主入口**：回答五个问题——我的猫是谁 / 今天发生了什么 / 昨天的干预有没有影响 / 现在什么状态 / 我今天还能做什么。结构：顶部状态卡（不堆数值）→ 今天最重要的故事 → **昨日建议回执**（让用户相信系统有记忆、选择有效）→ 今日干预（每天一个主要动作）→ **明日悬念**（下一次召回理由）。
4. **猫的长期档案**：生活记录（按日回看）/ 认识的猫（关系翻译成人话，不显数值）/ 物品与纪念（只展示有叙事意义的）/ 正在发生的故事（活跃事件线）。
5. **返回与召回**：站内书签引导 → 分享卡二维码 /c/{id} 主客分流 → 邮件提醒（绑定后）→ 浏览器通知与小程序后置。

## 公开页与主人页分离

主人视图：私密留言、建议、完整状态、全部日记、事件线。访客视图：公开资料、公开故事、分享卡、"我也领养一只"入口。增长闭环：主人分享 → 访客围观 → 访客领养。

## 首次领养体验（3 分钟内）

首页一句话 + 领养按钮 → 选基础外观（不等生图）→ 四个问题（名字/性格/生活/怎么称呼你）→ 立即出身份卡（AI 立绘异步替换）→ **立刻模拟到岛第一天** + 第一次选择 → 完成后再提示留邮箱。

## 页面集合

`/` 介绍+领养入口 · `/adopt` 创建 · `/my-cat` 今日核心页 · `/my-cat/history` 长期积累 · `/c/[publicId]` 公开猫主页 · `/account` 邮箱绑定。岛屿信息流降为二级入口。产品中心从"看整个岛"改为"看我的猫今天发生了什么"。

## 数据模型补充

User（含匿名）/ Adoption / UserSession / DailyIntervention / NotificationPreference / **CatDailySummary**（关键：headline、narrative、interventionResponse、stateChanges、relationshipChanges、tomorrowHook、publicVisibility——前台读摘要，不从 events 现拼）/ PublicProfile。

## 优先级

**P0（没有就不能测试）**：匿名用户与 Session；猫与用户绑定；/my-cat 今日页；历史日记回看；用户干预与次日回执；返回用户识别；首日立即生成事件。
**P1（用于有效测试）**：邮箱绑定找回；公开猫主页；分享回流；活跃事件线展示；NPC 关系展示；埋点漏斗。
**P2（验证后再做）**：微信登录；浏览器通知；用户间关注；多只猫；猫咪互访；商城付费。

## 验收标准（跨日体验）

用户今天首次进入 → 领养 → 看到第一天事件 → 留下建议 → 关站 → 第二天回来 → 系统认出用户 → 自动进入自己的猫 → 看到建议如何影响结果 → 再次选择。全链路无人工介入、无丢档、无重新领养、无身份错乱，才算闭环完成。

**最终压缩**：用户有一只永久属于自己的猫；猫每天持续生活；用户每次回来都能看到上一次干预产生的结果，并留下下一次干预。
