# doc/13 开发任务单:微信通道 + D1 封版收口

> 2026-08-01 下发。依据:doc/11(微信生命连接层)、doc/12(四个瞬间 + 二次拍板)。
> 现状:doc/10 主体已实施(码头相遇页/心理选择题/goodnight/firstWords/first_meeting 引用规则/相遇照片);
> 本单只含**未实施**部分。按批次顺序开发,批次内按编号。

## 全局红线(每个任务都受约束)

1. **事实先行**:微信消息、first_impression、小秘密全部走"模拟器/规则产事实 → LLM 只包装"管线,任何一句猫的话不允许由通道层或前端生成;
2. **openclaw 哑管道**:openclaw 自带的 LLM 自动回复必须关闭,入站消息一律回传后端,出站消息只发后端叙事产物;
3. **口径词禁用**:用户可见文案禁止出现"绑定/授权/通知/加载中/生成中/步骤/任务/微信绑定"(内部代码与埋点随意);
4. **D1 封版**:不得为本单任何功能在首日流程新增页面、弹窗、按钮(doc/12 §八.1);
5. **出站消息一律先过 24h 窗口检查**,窗口外消息绝不硬发。

## 批次一(P0):微信通道 MVP —— doc/11

### T1 通道数据层
- 新表(命名参考):`Channel`(userId、kind: wechat_openclaw | email、externalId(wxid)、windowOpenUntil、boundAt、mutedAt);`PairingCode`(code、userId、catId、expiresAt、usedAt);`OutboundMessage`(userId、kind、content、status: sent | window_closed | failed、sentAt)——窗口外未发出的消息落库,供"未寄出的信"读取。
- 绑定资产落 userId,不落微信号(doc/11 §八.2 通道抽象)。
- 验收:换 externalId(模拟换号)不丢绑定历史;email 通道可挂到同一抽象下。

### T2 openclaw 对接(入站/出站)
- 出站:后端 → openclaw 发送接口;入站:openclaw webhook → 后端(签名校验)。
- 入站分流:未绑定 wxid + 文本命中 PairingCode → 配对;已绑定 → 落留言(T5);其他 → 口令容错回复("口令不对,再看一眼你家猫的页面?")。
- 每次用户入站消息刷新 windowOpenUntil = now + 24h。
- 验收:配对/回信/无效消息三条路径联调通过;openclaw 侧自动回复确认关闭。

### T3 绑定 UI(两处曝光,零新增节点)
- 主曝光:登记完成亮相屏(照片+立绘亮相处)追加区块——文案定稿(doc/12 §二.3):"明天它醒来的时候,可能会想告诉你一些事情。你愿意让它找到你吗?"按钮「让它找到我」→ 展开二维码 + 口令(格式"纪念物词-三位数",复用 CopyCode 组件);
- 二曝:goodnight 页同款区块(未绑定者);
- 配对成功后 Web 侧出现「✓ 它找到你了。」(justDone 同款庆祝态,轮询或刷新可见);
- 「第一天的小约定」第三件改为"给它留一个能找到你的方式"(微信优先、邮箱次选,doc/11 §四兜底)。
- 验收:绑定先于留言的变体路径可走通;文案无禁用词。

### T4 握手消息(人格分池)
- 配对成功即发,唯一的即时消息,**豁免 22-8 静默**;
- 按性格主轴分池(确定性选池,非 LLM):胆小/社交/勤劳三版 + 夜晚变体("这么晚呀。我也刚到,睡不着。明早说给你听。"),叠加口癖(lib/narrative/voice.ts 现成);
- 已留 firstWords 则引用原文;未留则反向引导"回岛给它留一句";
- 消息以「🐱 {猫名}:」开头(1:1 直连规范,doc/11 §五)。
- 验收:三性格 × 昼/夜 × 有/无 firstWords 共 12 个组合抽查,无编造事实。

### T5 回信即留言
- 已绑定用户入站文本 → 落 ownerNudge(当天未消费的合并为最新一条)→ 明早 tick 照常消费;
- 即时 ACK:猫第一人称确定性短句,按心情分池(复用 petLine 机制),绝不接续聊天;连发多条提示"一天捎一句,它记性好";
- 支持退订口令(如"别再捎信")→ mutedAt。
- 验收:微信留言与 Web 留言在 D+1 日记回应中等效;ACK 永不调用 LLM。

### T6 D2 兑现消息(每日出站任务)
- tick 叙事完成后触发:向"昨日绑定、今晨在窗口内"的用户发 D2 消息;
- 内容取材规则(不许编):今晨 morning 主事件的 factSummary 改写 + interventionResponse 摘句 + 回岛链接;由叙事层生成(带口癖),失败用模板兜底;
- 发送时间 8:00-8:40 随机打散;每人每天全类型合计 ≤1 条;
- D3+ 事件触发白名单(第一次交到朋友/事件线关键步/D7 纪念册/店开张)与缺席 3 天关怀,同一条发送管线,同一频控。
- 验收:干跑环境模拟 7 天,无一天超 1 条、无窗口外发送、无静默时段发送(握手除外)。

### T7 未寄出的信
- 窗口关闭时 OutboundMessage 落 status=window_closed;/my-cat 出现「它写给你、没寄出去的信」+ 提示"在微信回它一句,信就能寄到了";只展示最新一封;
- 关键事件(D7 纪念册)同时走邮件兜底;已绑微信用户停发每日邮件(双通道去重)。
- 验收:窗口过期 → 信出现在 Web;用户微信回一句 → 下一条恢复微信送达。

### T8 通道监控与自动停发
- 监控:送达失败率、被拉黑/删好友数、窗口外丢弃数;连续异常(阈值可配)**自动停发全部出站**并告警;
- 后台(admin)可一键暂停通道。
- 验收:模拟连续失败触发自动停发。

- 验收:分享卡/亮相页/生活册三处标签一致。

## 批次三(P1):体验细化

### T12 船靠岸等待叙事
- 登记提交后 → 亮相前的等待期(立绘+照片异步生成):三段轮播文案「船正在靠近猫啊岛。」→「棉花已经在码头等你。」→「它好像有点紧张。」,禁止任何 loading/生成中字样;
- 超时兜底:超过阈值先亮相文字与棉花,照片"晚点洗出来,洗好第一时间给你";生成失败不阻塞认领(doc/12 §八.9)。
- 验收:断网/超时/正常三态走查。

### T13 外貌去参数化
- "它长什么样?"自由文本框 → 「你第一眼注意到它哪里?」四选一(毛茸茸的大尾巴/圆圆的眼睛/小小的耳朵/总是乱糟糟的毛)+ 可选补充框"如果你愿意,也可以告诉我们更多";
- 选择映射立绘描述词,补充文本拼接;存量 appearance 字段兼容。
- 验收:四选一 × 有/无补充,立绘生成质量抽查。

### T14 first_impression(猫对主人的第一印象)
- firstWords 提交时确定性生成(素材池 × 两输入映射:三道心理选择题结果 + firstWords 特征[长短/有无安抚词/有无称呼]),**不调 LLM**;
- 落 MemoryEntry kind=first_impression;露出两处:亮相屏一行 + 首日日记"对你的第一印象"段引用同一条事实;
- 引用规则同 first_meeting 家族(防复读)。
- 验收:同一输入永远同一印象;日记与亮相屏表述同源不矛盾。

### T15 小秘密长期槽位
- 首日小秘密从候选池选定(藏叶子/数第一句话字数/没关门/收小东西),落结构化事实,**不给钥匙**;钥匙在首日日记至多一句陈述;
- 不每天生成新秘密;预留"后续被重新发现"读取口径(Day30 回响),本期不做触发。
- 验收:首日日记结构 30/30/20/20 中"小秘密"段取自该事实。
