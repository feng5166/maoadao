## 一、这一版到底要解决什么

**北极星（本轮唯一判据）**：

> 让用户相信——**这只猫不是系统生成的，是我刚好遇见的。**

现在的流程是：进岛 → 填三道心理题 → 生成猫 → 领养。本质上用户在对系统说
"请给我生成一只适合我的猫"，这是 AI 产品逻辑，不是宠物关系逻辑。

现实里人和猫的关系不来自匹配，来自**事件**：它第一次靠近你、第一次睡你旁边、
第一次叼东西给你。宝可梦最强的地方不是皮卡丘参数匹配度最高，而是那只精灵
刚好在那个时间那个地点遇见了小智。

**结论：D1 缺的不是猫，是一段"第一次在猫岛上的经历"。**

### 为什么需要一点游戏结构

情感需要时间，但 D1 没有时间。游戏结构在这里不是目的，是**加速器**——它是
"制造第一次事件"的手艺。但边界必须清楚：

| 要的 | 不要的 |
|---|---|
| 探索、发现、互动、留痕 | 任务、资源、数值养成、每日签到 |

第二条判据（叠加使用）：**结果由猫决定的可以做，由用户操作/资源决定的不做。**
"摸摸它"安全，"留句话看它听不听"安全；签到、经营、地图探索玩法不安全。

**第三条判据·猫化测试（二轮评审补入，最硬的一条）**：

> 把这段描写里的猫换成狗、小狐狸、小机器人——**如果依然成立，就不合格。**

生命遭遇 ≠ 猫的遭遇。"睡觉""等待""看着你"任何生物都能做；
**收藏与占有、对小东西的执念、对地点的固执、忽远忽近的距离感**才是猫。
所有 D1 文案必须过这一关。

同时的反向红线：**猫化不等于拟人化**。猫不会"等一艘不会回来的船"（那是人的心事）；
猫会**守着同一个位置**，而"等船"是岛上人的猜测。凡是要给猫安一段心事的，
一律把解释权推给旁人（岛民、日报、邻居猫），猫本身只负责行为。

### 定位口径

- ❌ "AI 猫岛养成" / "领养一只 AI 猫" / "冒险岛"（"冒险"会拉来期待玩法的用户，期待错配即流失）
- ✅ **"登上一座岛，遇见一只猫"**
- 长口径：一座猫生活的岛，你可以偶尔回来看看属于你的那只猫。

猫岛 = **治愈型探索空间**。参照动森的生活感、Neko Atsume 的等待感、
宝可梦的偶遇感、光遇的空间感；不是 RPG。

## 二、剧本（七拍）

全程目标 **90 秒内见到猫**，180 秒内走完。每一拍都要么在推进相遇，
要么在收集必要数据——**没有一拍是纯风景**。

### 拍 0 · 船票是仪式，不是检票口（约 5 秒）

现在船票号是登记表的第一栏，用户上岛第一个动作是"验票"。改为：

- **走深链进来的（`/adopt?ticket=…`）**：完全不出现输入框。画面上是一张已经在手里的票，
  票根被撕下 → "你的船到了。"
- **没有票的**：才出现输入，措辞是"上岛要有人带——找给你介绍猫啊岛的人要一张船票"。

> 深链带票能力已具备（`/adopt?ticket=` → 注册页自动填入）。

文案示例：

```
船靠岸了。
[票根图]  猫啊岛 · 单程 · 仅限一位岛民
                                    〔登岛〕
```

### 拍 1 · 登岛（约 30 秒，可跳过）

不给猫，先给**世界**。用已有的码头场景（含时段变体：morning / dusk / night），
配环境声（海浪/风/鸥鸣，音效模型生成，**不用人声**）。

三行字，逐行浮现（复用 `.fx-rise` / `.fx-rise-2`）：

```
风是咸的。
远处有猫叫，但看不见猫。
沙地上有一串脚印，往岛里去。
```

底部：**〔跟上去〕**

> 设计要点：这 30 秒建立的是"这地方本来就在运转，我是后来的"。
> 必须可跳过（右下角小字"直接去岛上"），Web 用户耐心预算很短。

### 拍 2 · 第一次选择：往哪边走（收 boldness）

三个方向，**不是心理测试，是行动**。用户不知道自己在选性格。

**动机必须是好奇，不能是性格**（二轮评审）。前台一个性格词都不许出现——
用户在选"我被哪儿吸引"，不是在选"我要什么人格的猫"。一旦让人闻出
"这是人格路线选择"，就退回成问卷了。

| 方向 | 画面钩子（好奇驱动，非性格） | 场景资产 | 后台收集 |
|---|---|---|---|
| 海边礁石 | 潮水退下去了，礁石底下好像卡着什么东西 | `reef.jpg` | boldness 高（≈82，原 `dash`） |
| 松林小径 | 林子里有窸窸窣窣的动静，一停下来就没了 | `pines.jpg` | boldness 中（≈52，原 `slow`） |
| 灯塔坡 | 灯塔顶上的灯还亮着——好像有人忘了关 | `lighthouse.jpg` | boldness 低（≈25，原 `watch`） |

三个地点的图 + 四时段变体**都已在库**（`public/scenes/`）。夜里登岛自动走
night 变体，"灯塔的微光"在夜里最成立，白天则改写为"灯塔的门开着"。

> **视觉硬约束**：方向不用 emoji（用户侧禁 emoji）。需要在 `components/icons.tsx`
> 按现有手绘风格补三枚：礁石 / 松树 / 灯塔（灯塔图标已有 `IconLighthouse`）。

### 拍 3 · 遭遇：它已经在那里（收 sociability）

**关键：不是"生成了一只猫"，是"你撞见了一只猫"。**

三段遭遇全部按**猫化测试**重写——每一段的行为都必须是猫特有的
（收藏与占有、对小东西的执念、对地点的固执），换成狗或狐狸就不成立：

```
【海边】
一只猫正把一枚比它脑袋还大的贝壳往岩缝里拖。
拖两步，滑回去一步。它换了个角度，再来。
它发现了你——停住，尾巴尖动了一下。
```

```
【松林】
它把一片羽毛按在爪子底下，风一掀就重新压住。
按了很久，也没打算把它怎么样。
你踩到一根枯枝，它抬起头。
```

```
【灯塔】
它每天傍晚都坐在同一块石头上，朝着海面。
岛上的人说，以前有条船。
它听见脚步，耳朵转过来，身子没动。
```

> 灯塔线特别说明：**"等船"是岛民的说法，不是猫的心事**。猫只负责
> "固执地守着同一块石头"这个行为，解释权在旁人——见 §一 的拟人化红线。

#### 你的动作，与**第一次拒绝**（本拍的情感核心）

这里是 D1 唯一一处"关系发生变化"的地方，必须给足。用户先做一个动作
（收 sociability）：

| 用户动作 | sociability | 猫的反应 |
|---|---|---|
| 蹲下来，朝它伸手 | 高（≈82，原 `greet`） | **退开一步**，看着你 |
| 站着不动，等它 | 中（≈50，原 `wait`） | 盯了你一会儿，没动 |
| 不看它，自己往前走两步 | 低（≈22，原 `alone`） | 跟了两步，又停下 |

**三条都不给"成功"**。然后画面停住，只剩环境声，**不给任何按钮**——
唯一的提示是一行小字：

```
（它没走远。）
```

停 3–5 秒后，它自己回来。

> **设计红线**：拒绝之后的靠近**绝不能由用户再点一次触发**。给了重试按钮，
> 这就变成"操作失败→重试成功"的关卡逻辑，是本文档反对的一切。
> **D1 唯一"正确"的操作是不操作**——游戏教人做得更多，猫教人别动。
> 这一拍也是全产品"结果由猫决定"这条判据最纯粹的一次示范。

拒绝对三轴**不产生任何影响**，三条路径的后续完全一致——它不是考题，
用户不会"选错"。

第三轴 diligence 由**它当时在做什么**决定（拖贝壳=忙碌 82 / 按羽毛=看心情 52 /
守着石头=懒 25），不再单独问用户——**这一轴改由猫自己交代**，
这正是"它有自己的性格，不是你设定的"。

### 拍 4 · 第一眼看清 + 第一声猫语

它停下的那一刻，问一句（这题现在就在表里，只是换了语境）：

```
它离得够近了。你最先看清的是——
〔毛茸茸的大尾巴〕〔圆圆的眼睛〕〔小小的耳朵〕〔总是乱糟糟的毛〕
```

→ 直接喂现有 `firstSight` → `appearance`（生图 prompt 用）。

#### 第一声猫语 = maoadao 的声音标识（二轮评审升级为 P0）

同一刻播第一声（doc/17 引擎，新增 context `first_meet`）。这不只是一个音效——
**这是全产品第一次出声，是"猫不说人话"这条差异化的听觉签名**，
地位等同于 Sowii 的"嘟嘟"。因此不能只规定"短、轻、带疑问"，
**每只猫的第一声必须不一样，而且以后能靠声音认出它**。

好消息：参数体系**已经存在**。`catVoiceProfile(cat)` 会按猫的属性给出
`baseTimbre`（young / normal / deep）、`pitchOffset`、`volumeOffset`、
`vocalFrequency`（爱不爱叫，随社交度）。first_meet 要做的是让这组差异
**在第一声就被听出来**，而不是被通用音效抹平：

| 猫的倾向 | 第一声的形态 |
|---|---|
| sociability 高 / young | 短促上扬，一声就够——「咪！」 |
| 中间态 / normal | 一声拖尾 + 停顿，像在确认——「喵……」 |
| sociability 低 / deep | 极轻，几乎听不见——「……喵。」 |

**「它的第一声」要留下来**：存进已有的 `CatVoiceNote`（海螺留声位），
在相遇档案里可回放。它不单列为第五件私人资产，而是**「我的第一次」这件事的一部分**——
但它是唯一一件能被**听见**的 D1 资产，传播价值单独算。

> 全程**不用人声**（doc/17 拍板，与 Sowii"只嘟嘟"同一判断）。

> **叙事红利**：立绘是领养后异步生成的（10–30 秒）。所以"第一眼看不清全貌"
> 不是妥协，正好是剧本要的——逆光、树后探头、只看到尾巴。等立绘好了，
> 第一次看清它的全身，那是 D1 的第二个高潮（现有 `BoatArriving` 组件承接）。

### 拍 5 · 名字来自岛上，不是你取的

**这一拍的顺序改动最重要：名字是关系的结果，不是关系的前置设定。**

```
它脖子上挂着一块褪色的小牌子。
上面写着：灰灰。
岛上的居民也都这么叫它。
```

- 系统按外观/性格从确定性名字池取名（不走 LLM，避免 OOC 与延迟）。
- **用户仍然可以改名**——现有"名字想改一下？机会只有一次"（`cat.renamedAt`）
  的机制正好承接，而且此刻它的含义变了：不是"给我的宠物起名"，
  而是"我想换一个只有我这么叫它的名字"。这比让用户先填名字动人得多。

### 拍 6 · 第一份礼物 = 拒绝的解除动作（不是任务）

**不要做"帮猫找回铃铛"——那就变成任务了。** 应该是**它送你的第一件东西**。

**结构合并（二轮评审）**：原稿把"拒绝"放在拍 3、"礼物"放在拍 6，隔了两拍，
情感是断的。改为**同一条弧**——它退开、犹豫、然后叼起那件东西推到你脚边。
**送礼就是拒绝的解除动作**，一气呵成：

```
它退开的那一步，还站在原地。
盯着那枚贝壳看了很久——
它本来是要把它藏起来的。
最后还是叼起来，推到你脚边，
然后先一步往小屋的方向走了。
```

关键不在"给了什么"，在**"它本来想留给自己"**。礼物之所以重，是因为它是一次
**取舍**，而这次取舍只有猫化的前提成立才有意义：拍 3 里它费劲拖贝壳、
按着羽毛不放，正是为了让这一刻的放手有分量。

| 路线 | 礼物 | 它本来想拿来干嘛 |
|---|---|---|
| 海边 | 那枚拖不动的贝壳 | 要拖进岩缝里藏起来 |
| 松林 | 那片压在爪子下的羽毛 | 按了很久，不让风吹走 |
| 灯塔 | 石头缝里的一小截旧绳结 | 每天来，每天扒拉两下 |

落库：先用现有 `MemoryEntry`，新增 `kind = "keepsake"`（现有 kinds:
observation / relation / emotion / thread / semantic），`visibility = "public"`，
`importance = 5`。这样它天然进日记素材与记忆检索。

### 拍 7 · 它怎么叫你 + 你的第一句话 → 小屋留痕

最后两问保持不动（现有 `ownerNick` / `firstWords`），但语境变了：

```
它在小屋门口停下，回头，像在等一个称呼。
「以后它该怎么叫你？」  〔________〕

第一次见面，你想对它说什么？
〔________________________〕
它会记一辈子。
```

进小屋，收尾画面：

```
门口的木箱上，多了一枚贝壳。
—— 灰灰留下的东西
```

**D1 结束时用户手里有四件东西**：一只**遇见**的猫、一件它给的礼物、
一张相遇照片、一句它记住的话。

## 三、数据接口：三轴怎么在走路里收齐

v2 不改后端契约，`adoptCat` 的入参一个不少。对照表：

| 现有字段 | v1（表单） | v2（剧本） |
|---|---|---|
| `boldness` | 第二页问"到陌生地方会——" | **拍 2 选方向** |
| `sociability` | 第二页问"遇到不认识的猫——" | **拍 3 你的动作** |
| `diligence` | 第二页问"太阳好的下午在——" | **拍 3 由猫当时在做什么决定** |
| `firstSight` | 第一页"第一眼注意到哪里" | **拍 4 原句照搬** |
| `name` | 第一页用户填 | **拍 5 系统给 + 保留一次改名** |
| `ownerNick` | 第三页 | 拍 7（不变） |
| `firstWords` | 第四页 | 拍 7（不变） |
| `ticket` | 表单第一栏 | **拍 0，深链自动带入** |
| `goal` | 第二页"你猜它想过什么日子" | **砍掉**，由三轴推导 |
| `tags` / `appearance` / `bio` | 选填 | **砍掉自由输入**（appearance 由 firstSight 单独生成） |

组合数不降级：3（方向）× 3（动作）× 3（猫的状态由方向内随机）= 27 组，
与原问卷一致。

**砍 `goal` 的理由**：它是唯一一道纯"设定"题（你替猫决定它想要什么人生），
和"它有自己的意志"这条核心资产直接冲突。默认值由三轴推：
diligence 高→`earn`，sociability 高→`friends`，boldness 高→`explore`，否则 `chill`。

## 四、"三只初遇猫"怎么做到已经在那里

**叙事真实 ≠ 数据真实，这一点要诚实处理。** 三条路线上的猫在数据上仍然是
你选定方向那一刻才创建的（一个用户一只猫的模型不变），但用户感受必须是
"它本来就在那儿"。做到这一点靠三件事：

1. **它先于你出现**——遭遇描写里它在干自己的事，不是在等你。
2. **它先想走**——第一反应是跑掉/翻身/不理你，不是迎上来。
3. **它已经有名字**——名字来自岛上，不是你给的。

**没选的那两条路**：记进 `MemoryEntry(visibility=private)`。D3–D7 之间由海螺
或岛闻回收一次——"你上岛那天没走的那条路，今天有只猫从那儿过来了"。
低成本，情感回报高。〔P2，非 D1 必须〕

**相遇照片跟随相遇地点**：现在永远合成码头场景，v2 改成你**遇见它的那个地点**
（reef / pines / lighthouse），场景图和合成管线都是现成的。这让"相遇档案"
从一张通用卡变成只属于你的那一张。

## 五、IP 动作：「猫会叼回它觉得重要的东西」

> 二轮评审补入。这是本文档**战略价值最高的一条**——它解决的不是 D1，
> 是"为什么偏偏是它"和"怎么传播"。

Sowii 有"嘟嘟"，maoadao 需要一个同级别的、一眼认出的**招牌动作**。
拖贝壳、睡觉、守石头都只是场景行为，不是长期符号。招牌应该是：

> **猫啊岛上的猫，总会带回来一些它觉得重要的东西。**

### 为什么是这个动作

1. **极猫**。叼东西回家是真猫行为（而且是猫向人示好的经典方式），
   一眼过猫化测试，换成狗/狐狸/机器人都不成立。
2. **每天产生新内容**。它比"嘟嘟"强的地方在于：嘟嘟是一个**声音符号**，
   叼东西是一个**内容机制**——物件池可以无限扩展（贝壳、羽毛、旧纽扣、
   漂流瓶碎片、褪色的糖纸、半张船票……），每天都能长出新东西。
3. **自带分享单元**。"今天灰灰叼回来的是____"天然是一张卡片，
   直接接现有分享卡管线。用户会晒，而且晒的是**只有他有**的那一件。
4. **共通行为 + 独特产物**。所有猫都叼东西（这是岛的规矩，构成 IP 认知），
   但叼回什么由**性格 × 地点 × 关系深度**决定（这是"我的猫"）。
   和"所有蘑菇都突突"是同一种结构。

### 这条链已经建了一半

| 环节 | 现状 |
|---|---|
| 猫每天产生事件 | ✅ 模拟器已跑 |
| 猫叼回一件东西 | ⬜ 需要新事件类型 `bring_home` + 物件池 |
| 你给它起名字 | ✅ **海螺已有"物件命名"题型**（约每 12 天，D5+），名字进 `MemoryEntry(semantic)` 长期复用 |
| 收进小屋 | ⬜ 小屋收藏（路线 P3，待做） |
| 分享出去 | ✅ 分享卡管线 + 导演系统合成图现成 |

**也就是说这不是新建一个系统，是把已经零散存在的东西提到台前当招牌。**
D1 的第一份礼物就是这条链的**第一件藏品**——它天然是"我的东西"这件私人资产，
也天然是小屋收藏的第 1 号展品。

### 落地口径

- 世界观一句话（可用于内容账号简介、包装、分享卡页脚）：
  **"岛上的猫，总会带回来一些它觉得重要的东西。"**
- 频率：不是每天，**保持稀有**（约每 3–5 天一件）。天天叼就变成日常掉落，
  情感贬值；隔几天来一件才有"今天有惊喜"。
- 物件必须**可命名、可收藏、可回看**，且命名后在日记/岛闻里用用户起的名字复述。
- 与「第一次拒绝」的关系：D1 那一件是**它放弃收藏送给你的**，
  之后的每一件是**它专门带回来给你的**——从"割舍"到"惦记"，是关系的进展。

## 六、世界事件 vs 遭遇事件（这一版埋的第二颗种子）

这是讨论中另一个关键区分，**D1 之后长期有效**：

| | 世界事件（已有） | 遭遇事件（要补） |
|---|---|---|
| 产生 | 后台模拟：灰灰今天去了森林 | 用户进入时：你刚好撞见它 |
| 呈现 | 日报体：读到一条信息 | 遭遇体：你经过森林，看到它从树后探出头，嘴里叼着一片奇怪的叶子 |
| 感受 | 我知道了 | 我碰上了 |

事件池、事件链、《猫啊岛日报》**都已经在跑**，缺的不是内容是**呈现层**。
这一层不需要新系统：同一条事实，日报用第三人称过去时，遭遇用第二人称现在时。
归 doc/15 旁白规范的延伸，优先级排在 D1 剧本之后。

## 七、验收指标

### 定性验收：四件私人资产（二轮评审升为硬标准）

D1 结束时，用户必须**拥有**下面四件东西。少一件就是这一版没做完——
这比任何漏斗数字都更接近北极星：

| # | 资产 | 是什么 | 落在哪 |
|---|---|---|---|
| 1 | **我的猫** | 关系 | `Cat`（名字来自岛上 + 一次改名权） |
| 2 | **我的第一次** | 事件（遭遇 → 拒绝 → 靠近） | 相遇照片 + `MemoryEntry(first_impression)` + 可回放的第一声 |
| 3 | **我的东西** | 物证 | `MemoryEntry(keepsake)` → 小屋门口 |
| 4 | **我的那句话** | 记忆 | `firstWords`（它会记一辈子） |

**四件的共同点：都是独一无二、不可复制、且用户能指着说"这是我的"。**
这也是判断任何 D1 改动该不该做的最快方法——它增加了这四件里的哪一件？
一件都不增加就别做。

### 定量验收

D1 漏斗埋点**已经全埋好了**，直接可用：

```
landing_view → arrival_scene_view → adopt_start → adopt_complete
→ first_words_submit → first_story_view → pet_cat → intervention_submit
→ next_day_return / d2_promise_view
```

v2 需要新增的埋点：`island_step`（拍 2/3 各一次，带 choice）、`first_meet_view`、
`first_meow_play`、`refusal_wait`（用户在拒绝后等了多久 / 有没有直接划走——
这是验证"不操作"设计成不成立的唯一数据）、`keepsake_received`。

**判据（跑 30–50 个陌生用户，看一周）**：

| 指标 | v1 基线 | v2 目标 |
|---|---|---|
| `arrival_scene_view → adopt_complete` 完成率 | 待测 | ≥ 60% |
| 完成领养 → `first_words_submit` | 待测 | ≥ 80% |
| `next_day_return`（D1→D2） | 待测 | ≥ 40% |

> 参照系：Sowii（秃秃）在**没有 AI** 的早期版本上跑出次留 >80%、D30 50%。
> 留存不来自可玩性，来自"它自己活着"。v2 若不能显著改善 D1→D2，
> 说明问题不在心流，在更前面——那时候幸好还没有把一个冒险岛建出来。

## 八、不做（红线）

1. **不做任务系统**。"帮猫找铃铛"这类目标导向的委托，会把礼物变成奖励。
2. **不做资源/数值/签到**。鱼币是世界的一部分，不是给用户的进度条。
3. **不做地图探索玩法**。地图永远是偷窥窗口，禁点击导航/坐标（已有红线）。
4. **不做重选**。三选一之后不给"再看看别的猫"——可回头的相遇就退回成挑选。
5. **不加人声**。第一声猫语是喵，不是配音（doc/17 拍板）。
6. **不用 emoji** 做方向图标，按 `icons.tsx` 手绘风格补图标。
7. **不扩生态**。这一版不讨论多猫、社交、Petverse。
8. **不给"再试一次"**。拒绝之后不出现任何让用户重新示好的按钮——
   它自己回来，或者不回来（本版：一定回来）。
9. **不把猫写成人**。它可以固执、可以护食、可以不理你；
   它不能有心事、不能等一个人、不能懂事。心事一律由旁人来猜。
10. **叼东西不做成每日掉落**。稀有才有惊喜，约每 3–5 天一件（§五）。

## 九、待拍板的开放问题

1. **登岛 30 秒是否默认可跳过**？（倾向：可跳过，但跳过的人直接进拍 2，不跳过整段流程）
2. **老用户回访是否重放剧本**？（倾向：否。剧本只对没有猫的身份触发一次）
3. **改名机会的措辞**：在拍 5 当场给，还是留到 D1 结束后的小屋里给？
   （倾向：留到小屋，当场改名会削弱"名字来自岛上"的设定）
4. **深夜登岛**：夜里三个地点的遭遇描写要单独写一版，还是复用日间文案 + 夜景图？
   （倾向：灯塔线必须有夜间专用文案，另两条复用）
5. **拍 6 的礼物**是否立刻可见于小屋，还是次日早上才出现在门口？
   （倾向：立刻可见——D1 的即时反馈本来就稀缺）
6. **拒绝之后的等待时长**：3 秒还是 5 秒？（倾向：3 秒起，用 `refusal_wait`
   数据校准。太短没有失落感，太长用户以为卡住了——这是全剧本唯一需要实测调参的地方）
7. **「叼回小东西」什么时候上**：是跟 D1 一起做（第一件藏品就是 D1 礼物），
   还是等小屋收藏（P3）先落地？（倾向：**D1 一起做**——招牌动作越早立越好，
   而且第一件藏品放在门口就够了，不必等完整的小屋系统）
8. **物件命名是否前移**：海螺现有的"物件命名"题在 D5+ 才出现。既然 D1 已经
   有了第一件藏品，要不要让 D2 早晨的第一封海螺就问"这枚贝壳，你想叫它什么"？
   （倾向：要——这是 D1→D2 最强的一个钩子，而且题型现成）
