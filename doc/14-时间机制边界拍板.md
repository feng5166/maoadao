# 时间机制边界拍板：一个世界日 + 每猫入场准入

> 2026-08-02 拍板。时间系统总定义收敛为：
> **猫啊岛只有一个全局世界日，由北京时间早八每日推进；每只猫通过独立的入场准入状态接入这个世界。
> 模拟器提前生成确定性事实，展示层按时间或相遇流程逐步揭示，LLM 只负责对既有事实进行可追溯表达。**
>
> 本文写死进入正式开发前的边界。优先级最高的三项：
> ①早八前领养的 D1 最短生命周期 ②D1 独立于正常时段门的展示规则 ③叙事失败不能无限冻结世界。

## 一、D1 是每只猫的入场阶段，不是第二套时钟

- 全局只有 `WorldState.day`；入场状态落在猫身上：
  ```
  Cat.arrivalWorldDay   领养时的世界日（身份事实，显式保存，不再由首个事件倒推）
  Cat.firstTickDay      第一次参与 tick 的世界日（即"准入门"，见 §二）
  ```
- `lifecyclePhase` 不单独落库——由 `world.day < firstTickDay ? ARRIVAL : NORMAL` 推导。
  理由：可推导的状态落库就是第二份真相，迁移/修数时会俩打架。
- 事件是内容事实，不承担"猫龄"这种身份事实；补写/清理事件不得改变猫龄。
  现有 `catDay = world.day - firstEvent.day + 1` 全部改读 `arrivalWorldDay`。
- 存量猫迁移：`arrivalWorldDay` 用现有首事件日回填一次，此后不再依赖。

## 二、早八前领养的 D1 截断问题（准入门规则）

**问题**：07:55 领养 → 08:00 tick → 五分钟进 D2，摧毁首日 Aha/晚间留言/离岛仪式/D2 承诺可信度。

**规则（与评审稿的差异见下）**：

```
距下一个早八 ≥ 2 小时 → firstTickDay = 明天的世界日（参加下一次 tick）
距下一个早八 <  2 小时 → firstTickDay = 后天的世界日（跳过最近一次 tick）
```

| 领养时间 | 距早八 | 进入 D2 |
| --- | --- | --- |
| 14:30 | 17.5h | 次日 08:00 |
| 23:30 | 8.5h | 次日 08:00 |
| 03:00 | 5h | **当日 08:00**（用户在睡觉，醒来正好 D2） |
| 07:55 | 5min | 次日 08:00 |

**阈值取 2 小时而非 6 小时的理由**：D1 完整性的度量是"用户清醒着走完相遇流程"，不是钟点数。
深夜（0-6 点）领养的用户完成相遇流程后就去睡了——D1 在睡眠中自然结束，
早八醒来第一篇日记准时送到，恰好兑现"明早八点"的承诺；若跳过反而承诺落空
（goodnight 页说了"明早八点写好"，8 点却什么都没有）。真正的病例只有"清醒着被截断"，
即 6-8 点这最后两小时。阈值可由内测数据再调，但**最短 D1 生命周期必须存在**。

**引擎侧**：tick 模拟时跳过 `firstTickDay > targetDay` 的猫（无事件、无叙事、状态不动）；
其未消费的留言保留到它的第一次 tick（D2 兑现弹药不丢）。

## 三、D1 展示豁免时段门

```
D1（ARRIVAL 阶段）：按相遇流程与用户行为逐步揭示——码头相遇/登记/亮相/第一句话/
  此刻状态（深夜领养直接夜晚变体）/钥匙作为离岛前的小发现。不受 8/13/18 点时段门约束。
D2+（NORMAL 阶段）：按现实北京时间逐时段揭示（doc/09 §5 不变）。
```

实现口径：`lifecyclePhase === "ARRIVAL"` 时 unlocked = 全部时段、nowLine 走到岛专用状态集。
D1 是一段完整的"入岛微型时间"，D2 才接入全岛公共时间。

## 四、叙事自愈熔断：事实层必须前进，叙事层可以迟到

原则：**可以暂时没有优质日记，不能因为一篇日记让世界停转。**

```
gap 首次发现        → 本次 cron 只补叙事不推进（现状不变）
同一天第 2 次仍有 gap → 缺失者直接落兜底叙事（narrateOwnerDay 的 fallback 模板）
同一天第 3 次仍有 gap → 记 dead letter，世界照常推进；缺的日记事后可由 renarrate 补写
```

计数与观测挂在 §七 的 TickRun 上（`narrationAttempts / lastNarrationError / errorSummary`），
不给猫加字段。注意现状：narrateOwnerDay 自带模板兜底，走到"连兜底都失败"基本是数据毒丸
或写库故障——熔断是给这类病例兜底的，不是常态路径。

## 五、确定性的准确表述与叙事溯源

- **确定性复现**：事件、天气、状态与关系变化（`hash(day, catId)` + 纯函数天气）。
- **事实一致、措辞不保证逐字复现**：日记。重新生成时不得引入事实之外的内容（提示词已禁止，保持）。
- DiaryEntry 已有 `eventIds`（sourceEventIds）、`generatedBy`、`createdAt`；补齐：
  ```
  promptVersion    提示词版本号（narrator 里定义常量，改提示词时 bump）
  modelId          实际使用的模型
  ```
  能回答：这段话来自哪些事实/哪版提示词/为何重生成后措辞变了/是否事实越界。

## 六、用户干预的时间语义（统一口径）

- **正常日一切留言/建议只影响明天**（下一次 tick 消费）。文案红线：
  - ✅「明天它可能会想起你的话」 ❌「看看它今晚会不会听你的」
  - 现有 my-cat / cats/[id] 文案已合规，新增文案沿用此口径。
- **唯一例外：D1 的 firstWords**，由 `generateArrivalDay` 在相遇流程里即时消费（本文即为其成文依据，
  防止"留言即时改写当日事实"的需求膨胀）。
- **微信通道的双语义**（通道正在开发，现在写死）：
  - 「捎话给猫」→ 落 OwnerNudge，次日 tick 消费——和网页留言同一语义；
  - 通道内的即时寒暄/回执 → 通道层行为，**不产生事实、不改当日模拟**。
  - 微信里的猫可以"回话"，但它回的是已发生的事实与记忆，不是新模拟。

## 七、执行方式的扩容边界（现在只加观测，不重构）

全猫单事务 + `WorldState.day` 条件更新在内测规模是对的。现在只加 `TickRun` 表：

```
TickRun { targetDay, status, startedAt, simulationCompletedAt,
          narrationCompletedAt, narrationAttempts, errorSummary }
```

作用：④的熔断计数器 + tick 可观测性（现在失败只能翻 Vercel 日志）。
未来猫多了自然演进为「抢占目标日 → 分批模拟 → 每猫幂等落库 → 全部完成才提交 world.day」，
产品时间模型不变，只换执行方式。

## 八、时间系统与 D1 Aha 的分工

| 机制 | 证明什么 |
| --- | --- |
| generateArrivalDay（即时，不依赖 tick） | 这是一只属于我的、记得我的猫 |
| 次日 tick | 我离开后，它真的继续生活了 |
| D2 微信召回 | 它不仅继续生活，还兑现了找我的承诺 |

时间系统不抢 D1 的戏；tick 的任务是第二层证明。

## 实施顺序建议（估时约 1 个工作日）

1. `arrivalWorldDay` + `firstTickDay` 落库与回填，catDay 改读（0.3d，含引擎跳猫）
2. D1 展示豁免时段门（0.2d）
3. TickRun + 叙事熔断（0.3d）
4. 溯源字段 promptVersion/modelId（0.1d）
5. 文案审计一遍时间语义（0.1d）
