# doc/12 D1 定稿:四个瞬间——控制设计感的收敛修订

> 2026-08-01 拍板。对 doc/10(相遇重构)+ doc/11(微信通道)的产品负责人视角收敛。
> 方向不变、不加功能,只做三类修正:降任务感、强化传播资产、包装关系动作。
>
> **定稿判断:D1 已从"注册一只 AI 猫"进化为"完成一次数字生命的诞生"。
> 下一阶段的敌人是产品经理设计感——用户要的感受是:
> "我不是完成了一个流程,我只是刚好遇见了一只猫。"**

## 一、内外双口径:内部四资产,用户四瞬间

四资产(猫名/第一句话/相遇照片/微信绑定)**只作为内部指标口径存在,用户永远不感知**。
用户侧的 D1 是四个瞬间:

| 瞬间 | 体验 | 内部对应 |
| --- | --- | --- |
| ①「我遇见它」 | 码头 | adopt_complete |
| ②「它记住我」 | 第一句话 | first_words_submit |
| ③「它属于我」 | 相遇照片 | arrival_photo_view |
| ④「它找得到我」 | 微信 | 绑定成功 |

一切"完成态"隐藏:不出现步骤数、不出现清单腔、不出现"绑定/授权/通知"。
小约定完成态维持「今天,它记住了三件事。」;微信入口只有一句
「明天它醒来的时候,可能会想告诉你一些事情。你愿意让它找到你吗?」+ 按钮「让它找到我」,扫码放在点击之后。

## 二、P0(本轮就改)

### 1. 降任务感:所有完成态隐藏
- 页面上不出现"微信绑定"四个字(doc/11 的"让它找到你"贯彻到每一处文案);
- 四资产/四步骤等结构词只存在于文档与埋点。

### 2. 相遇照片 = 第一传播资产(重要性 > 第一篇日记)
- 照片上线**时间标签:「猫啊岛历 第 1 天」**;
- 传播定位:用户晒的是「我的猫来到猫啊岛第一天」,不是"我的猫发生了一个故事"(秃秃路径:先可晒,后有故事);
- 长线埋点:D30 回看时展示"这是 30 天前它第一次来到这里"(周年/月度回响,未来触发器)。

### 3. 微信包装 =「给它一个联系方式」
- 亮相峰值屏文案定稿:"明天它醒来的时候,可能会想告诉你一些事情。你愿意让它找到你吗?"
- 深夜绑定的握手消息**豁免 22-8 静默**(动作回执非推送),用夜晚变体:"这么晚呀。我也刚到,睡不着。明早说给你听。"

## 三、P1(紧随其后)

### 4. 猫对主人的第一印象(双向关系起点)
- firstWords 提交的同时,系统生成**猫对你的第一印象**并落为事实(MemoryEntry kind=first_impression);
- **确定性生成,不许 LLM 编**:素材池按两个输入映射——三道心理选择题 + firstWords 特征(长短/有无安抚词/有无称呼);
- 露出两处:亮相屏一行("它第一次见到你,觉得你说话的样子让它安心")+ 首日日记"对你的第一印象"段引用同一条事实。

### 5. 等待 = 船靠岸叙事(不是 loading)
- 提交登记后 10-30 秒:「船正在靠近猫啊岛。」→「棉花已经在码头等你。」→「它好像有点紧张。」
- 生成完成 = 船靠岸 = 亮相;
- **超时兜底**:超过阈值先亮相文字与棉花,照片"晚点洗出来,洗好第一时间给你"(洗照片也是世界观内动作)。

### 6. 握手消息人格化(微信是最强人格展示入口)
- 按性格主轴分池(确定性,非 LLM):
  胆小:"我确认了三遍,才敢给你发消息。" / 社交:"我已经迫不及待告诉你今天认识的新朋友。" /
  勤劳:"我整理好了我的小屋,才来找你。"
- 叠加口癖系统(doc/09 §6);夜晚变体见 P0-3。

### 7. 外貌去参数化
- "白色毛,蓝眼睛"式描述框有 AI 生成工具感。改为**「你第一眼注意到它哪里?」**选择
  (毛茸茸的大尾巴/圆圆的眼睛/小小的耳朵/总是乱糟糟的毛)+ 可选补充"如果你愿意,也可以告诉我们更多";
- 选择映射到立绘描述词,自由补充保留个性化空间。

### 8. 旧钥匙再降一调
- D1 日记里钥匙**至多一句陈述句**("它在门口发现了一根系着红绳的小钥匙。"),不展开、不设问;
- 首日日记的"小秘密"槽位**不给钥匙**,留给猫自己的观察(它偷偷藏了一片叶子/它数了你说的话有几个字);
- 首日用户该记住的是"我的猫",不是"钥匙"。悬念由用户自己长出来。

## 四、P2(多人化伏笔)

### 9. 船票 → 岛民推荐信
- 进门页:"这张船票来自:一位已经住在猫啊岛的岛民。"
- **官方批次署名问题**:种子用户的票来自官方,不是岛民——由 NPC 署名兜底("这张船票是棉花留给你的"),
  推荐信虚构对所有人成立,且第一代用户从进门起就欠一只 NPC 的人情——多人化的第一根线。

### 10. 第一代岛民身份体系
- 现在的每个用户都是"第一代岛民",不是游客;身份资产(岛民编号/登岛日)为 Phase 2 预留。

## 五、时间规则(定稿,解深夜领养)

**世界时间 ≠ 用户时间。D1 是全产品唯一豁免时段门的一天。**
- 任何现实时刻登岛,首日剧本完整播放(下午靠岸/傍晚钥匙照常在叙事里),完整仪式 > 现在感;
- 用户现实时间只影响**离岛仪式**:23:30 登岛 →"今天太晚了,煤球先睡觉"直接入夜;
- D2 起进入现实同步节奏(doc/09 时段门生效)。此规则写明,避免实现时与时段机制打架。

## 六、指标修订

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| first_words_submit | ≥80% | 不变 |
| **相遇照片查看率** | ≥95% | 新增,D1 小高潮的到达率 |
| **第一句话平均长度** | 观察指标 | 质量代理:"你好"和"不要害怕,我会来看你"价值不同 |
| 微信绑定率 | 30-50% | 不变 |
| **D2 主动回访** | 最高指标 | leave_for_tomorrow → 次日 first_diary_read,终审不变 |

## 七、不做

- 不再往 D1 加任何新节点(收敛令);
- 不把四资产/步骤感暴露给用户;
- 不让钥匙在首日获得叙事重心;
- first_impression 不走 LLM 自由生成。

## 八、采纳的修订(2026-08-01 二次拍板):第五瞬间与信任闭环

### 1. 第五瞬间:放手

D1 对外仍然只有四个可感知瞬间:**遇见它 → 它记住我 → 它属于我 → 它找得到我**。
"放手"是内部第五瞬间,不对用户增加步骤:

> 用户第一次离开,并相信猫会继续生活;猫记住主人答应会回来。

只复用现有 `/my-cat/goodnight` 页面,新增一条结构化事实:

```ts
{
  kind: "first_departure",
  ownerId, catId,
  content: "主人第一次离开，并答应明天回来",
  importance: 10,
  occurredAt
}
```

**明确禁止以此为理由新增页面、弹窗、按钮或任务。**

### 2. first_departure 防复读规则

importance=10 只代表它是重要关系事实,不代表每次叙事都应被检索。引用规则写死:

- D2 首次回访:必须引用,完成第一次承诺兑现;
- 普通日记:禁止高频引用;
- 用户连续缺席后回归:允许引用一次("你走了几天又回来了,像第一次那样");
- D7、D30 等阶段总结:可作为共同历史引用;
- 相邻内容不得重复使用同一措辞。

**重要记忆 ≠ 永久置顶记忆;重要记忆 = 在正确的关系节点被重新唤起。**(与 first_meeting 同款规则,doc/10 修订 2)

### 3. D2 双向履约

D2 不只是猫履约(醒来后告诉主人第一件事),同时是**主人履约**(答应回来,并真的回来了)。
用户 D2 首次返回时,页面必须先确认这一事实,推荐展示顺序:

```
你真的来了
→ 昨天的话它还记得
→ 它醒来后发生了什么
→ 今天它想告诉你什么
```

该句只在 D2 首次有效回访出现一次,不得成为常驻欢迎语。

### 4. 五元组完成判定(内部)

```
Identity + Relationship Seed + Ownership Asset + Reality Connection + Departure Trust
```

| 内部事实 | 用户感受 |
| --- | --- |
| cat_name | 我遇见它 |
| first_words | 它记住我 |
| arrival_photo | 它属于我 |
| wechat_binding | 它找得到我 |
| first_departure | 我离开后,它仍会继续生活 |

微信绑定是核心转化目标,但**未绑定微信的用户仍可生成 first_departure**——否则会把"生命信任"错误地等同于"渠道授权"。

### 5. world_phase 明确分层

```ts
type WorldPhase = "ARRIVAL_DAY" | "NORMAL_DAY";
```

- ARRIVAL_DAY:D1 唯一豁免现实时间门,确保相遇、亮相和安顿仪式完整;现实时间只影响离岛文案和握手消息版本;
- D2 起切换 NORMAL_DAY,完全进入北京时间同步;
- world_phase 是世界规则,不应依赖前端临时判断。

### 6. 船票三类来源

```ts
type TicketSource = "NPC_INVITE" | "RESIDENT_INVITE" | "ISLAND_EVENT";
```

- NPC 邀请:棉花等官方居民留下的船票(同时承担首个世界关系种子);
- 岛民邀请:已有用户转赠;
- 岛屿活动:开放日或特殊批次。

**官方种子票不得伪装成真实用户邀请。**

### 7. "小秘密"成为长期生命槽位

小秘密不再服务首日剧情钩子,而服务角色生命感。D1 候选:偷偷藏了一片叶子/数了主人第一句话有几个字/第一次进屋时没有立即关门/把某件无用的小东西收进抽屉。

规则:必须是结构化事实;可以在后续生活中被重新发现(Day30:"那片叶子已经被它保存了一个月");不要求推进事件线;**不得每天生成新的小秘密**;优先形成长期习惯、收藏或共同记忆。旧钥匙在首日日记中最多一句客观陈述,不占小秘密核心位置。

### 8. 长期认知的事实与表达分工

长期认知遵守与日记相同的事实边界:

```
可回放行为数据 → 规则或统计得出认知结论 → LLM 只负责将结论说得像这只猫
```

例:事实(主人多次提醒谨慎 + 猫冒险后主人没有责备 + 主人仍持续支持探索)→ 结构化认知("主人重视安全,但并不反对我探索")→ LLM 表达("你总让我小心一点,可我知道,你不是想把我关在屋里")。

reflect() 不得自行创造认知,只能表达已由事实层确认的结论。**每条长期认知保留 evidence_event_ids 或统计依据**——可回放、可解释、可纠错。

### 9. 延迟世界观化原则

> 不隐藏延迟,但把延迟解释为世界中的真实过程。

生成立绘 = 船还在靠岸;合成相遇照片 = 照片正在冲洗;叙事生成 = 它正在整理今天发生的事;超时 = 先展示已确定事实,资产随后补齐;失败 = 稳定兜底,不向用户暴露模型、队列或重试概念。**超时不能阻塞认领和首日关系建立。**

### 10. D1 封版:下一步只验证,不再增加首日功能

D1 设计进入冻结状态,仅允许修复:事实矛盾、流程阻塞、明显理解障碍、微信配对或召回故障、性能和移动端严重问题。

验证三个问题:① 用户是否真正完成"相遇";② 用户是否愿意让猫找到自己;③ 用户是否在 D2 回来兑现承诺。

核心指标:

```
first_words_submit / arrival_photo_view / wechat_pair_success / wechat_first_reply
leave_for_tomorrow / D2_wechat_wakeup / D2_first_return / D2_second_intervention
```

**这版追加后,D1 正式封版。后续优化依据真实漏斗数据,而不是继续从设计完整性出发增加仪式节点。**
