# 猫啊岛（maoadao.com）项目定义

> 本文为项目立项稿、PRD 总纲与技术设计的统一基线（2026-07-30 拍板）。

## 一、项目一句话定位

领养一只会记住你、自己生活、还会交朋友的 AI 猫。

猫啊岛是一座持续运行的 AI 虚拟岛屿。每个用户拥有一只固定形象、独立人格、长期记忆和持续生活轨迹的 AI 猫。

用户不需要持续操作或与猫无限聊天，而是每天回来看看：

- 我的猫今天去了哪里
- 遇到了谁
- 做了什么决定
- 与 NPC 的关系发生了什么变化
- 昨天埋下的故事是否继续发展

产品本质不是聊天机器人，也不是猫咪内容社区，而是：

**AI 虚拟生命 × 轻量世界模拟 × 电子宠物 × 自动内容生产。**

## 二、产品真正要验证什么

猫啊岛第一阶段不是验证"AI 能不能生成猫咪故事"，而是验证：

**用户是否会对一个持续存在、能够自主生活的虚拟角色产生牵挂。**

核心产品假设只有两个。

### 1. 牵挂假设

用户是否认为：

- 这是"我的猫"
- 它昨天经历的事情今天还会继续
- 它记得我，也记得其他角色
- 我不打开产品，可能会错过它生活中的变化
- 我会关心它接下来会怎么选择

主要指标：创建完成率；D1、D3、D7 留存；连续查看天数；人均七日打开次数；用户是否记住 NPC；用户是否主动询问后续剧情。

### 2. 传播假设

用户是否愿意把猫的生活内容分享到：微信、小红书、抖音、朋友圈、群聊。

主要指标：分享卡生成率；保存或点击分享率；分享回流率；分享带来的注册率；哪种人格、事件和表达方式传播效果最好。

## 三、目标用户

第一阶段目标用户不是传统重度游戏用户，而是：

- 喜欢猫、虚拟宠物和治愈内容的人
- 愿意接受 AI 角色和轻陪伴体验的人
- 喜欢分享人格梗、情绪梗和日常段子的人
- 没有时间玩重游戏，但愿意每天查看几分钟的人
- 对电子宠物、模拟人生、动森式世界有兴趣的人

用户每天投入时间可以控制在 1—5 分钟。

## 四、核心产品闭环

第一版产品只保留四个环节：

创建一只猫 → 猫在岛上自主生活 → 系统生成今日故事 → 用户查看、干预或分享

### 1. 创建猫

用户设置：猫的名字、基础外观、性格倾向、与主人的关系、希望它过什么样的生活。

系统生成：固定角色立绘、角色身份卡、结构化人格参数、初始小屋、初始目标、初始 NPC 关系。

用户不进行复杂捏脸，创建过程应尽量短。

### 2. 自主生活

猫每天在岛上经历三个时间段：上午、下午、晚上。

每个时间段产生：一个主要行动；零到一次社交互动；状态和关系变化；可能推进一条持续事件线。

用户即使不在线，猫也会继续生活。

### 3. 今日故事

系统从当天发生的事件中挑选最有表达价值的部分，生成：一篇主日记、一至两条岛屿动态、一张外部分享卡。

内容不是由大模型凭空编写，而是基于模拟系统已经发生的事实。

### 4. 用户干预

用户每天只需要做轻量干预，例如：给猫留一句话；建议明天去哪里；选择是否帮助某个 NPC；选择今天使用哪件物品；从两个方向中选择一个；给猫更换服装或房间。

用户影响角色，但不完全控制角色。

## 五、核心技术原则

**Agent 产生意图，模拟器产生事实，LLM 产生表达，导演系统控制节奏。**

这四层必须分开。

### 1. Agent：产生意图

猫根据性格、长期目标、当前状态、角色关系、历史记忆、用户干预，决定它"想做什么"。

例如：想去灯塔调查；想向阿福借钱；想躲开某只橘猫；想为主人准备礼物。

Agent 只能提出意图，不能直接决定结果。

### 2. 世界模拟器：决定事实

模拟器校验：地点是否开放；精力是否足够；是否拥有相关物品；NPC 是否愿意配合；关系值是否满足；事件是否符合当前阶段；世界规则是否允许。

**模拟器是唯一事实来源。**

例如猫想向阿福借 20 枚鱼币，最终可能：成功借到；被拒绝；只借到一部分；被要求先完成任务；触发新的关系事件。

### 3. LLM：负责叙事

大模型不能创造新的世界事实，只负责将事实加工成：日记、对话、新闻、账单、吐槽、分享文案、漫画脚本、短视频旁白。

应遵循：模拟器产出事实 → 事实写入数据库 → LLM 根据事实生成表达。而不是让 LLM 自由编写今天发生了什么。

### 4. 岛屿导演：控制内容节奏

岛屿导演不直接编剧情，而是调整事件权重。它负责判断：

- 最近是否过于平淡
- 是否连续发生负面事件
- 哪条剧情长期没有推进
- 哪些角色需要相遇
- 哪种事件已经重复过多
- 今天需要冲突、温暖、悬疑还是反转
- 哪个事件值得成为今日主内容

这是猫啊岛区别于普通 Agent 模拟实验的关键系统。

## 六、与斯坦福 AI 小镇的关系

可借鉴 Generative Agents 的核心认知框架：观察 → 记忆 → 检索 → 反思 → 规划 → 行动。

主要复用：Memory Stream 持续记忆流；基于近期性、重要性和相关性的记忆检索；Reflection 从具体经历形成抽象认知；Planning 根据目标形成每日计划；Agent 之间的信息传播；角色关系和群体行为。

但不能直接照搬。斯坦福 AI 小镇追求"Agent 行为是否像真实人类"；猫啊岛追求"角色行为是否持续可信，而且每天都值得用户观看和分享"。

因此猫啊岛需要增加：结构化世界状态、游戏规则引擎、持续事件线、剧情导演、内容价值评分、内容审核、Agent 分级和成本控制。

## 七、记忆系统

采用双层记忆。

### 1. 客观事实

由数据库维护：鱼币余额、物品栏、当前地点、健康和精力、店铺状态、债务、任务进度、关系数值、世界事件、已发生事件。

这些数据不能被大模型修改。

### 2. 主观认知

角色可以形成自己的判断：我觉得阿福在隐瞒什么；我不太信任那只橘猫；灯塔可能和旧铜铃有关；我发现自己不适合开餐厅。

角色的主观判断可以是错误的，但不能覆盖世界事实。

### 3. 记忆分类

- 观察记忆：发生过什么
- 关系记忆：与某个角色有什么经历
- 情感记忆：事件带来了什么情绪
- 情节记忆：长期事件线目前到哪一步
- 语义记忆：角色总结出的长期认知
- 主人记忆：用户告诉猫的可记忆信息

用户信息必须标记为：私密可记忆 / 可用于公开内容 / 禁止公开引用。

## 八、世界和 NPC 设计

MVP 阶段不做跨用户猫咪社交，先建立由官方 NPC 驱动的小型社会。初期准备 12—16 只核心 NPC。

1. **功能型 NPC**：岛长、商店老板、医生、邮差、渔夫——负责基本世界功能。
2. **剧情型 NPC**：神秘灯塔守猫、欠债的餐厅老板、寻找旧主人的流浪猫、声称见过海怪的老猫——负责持续事件线。
3. **社交型 NPC**：社牛橘猫、高冷白猫、爱八卦的三花、总想创业的狸花猫——负责冲突、关系和轻喜剧。
4. **背景型角色**：不运行完整 Agent，只提供岛屿密度、新闻背景、群体事件、市场和街道氛围。

不同 NPC 使用不同 Agent 复杂度，避免全部角色每天调用完整大模型。

## 九、事件和剧情系统

不是完全随机生成日常，而是：

规则筛选 → 权重抽样 → Agent 提出意图 → 世界规则校验 → 结果落库 → 事件线推进 → 生成叙事

### 事件必须具备的要素

触发条件、参与角色、地点、前置状态、性格影响、关系影响、资源变化、后续事件、重复冷却、内容价值。

### 持续事件线

事件不能全部一天结束。例如"灯塔异光"可以持续一周：

1. 听说灯塔夜间发光 → 2. 获得旧铜铃 → 3. 发现阿福有所隐瞒 → 4. 尝试前往灯塔 → 5. 遇到阻拦 → 6. 找到隐藏房间 → 7. 选择是否公开秘密

持续事件线提供：悬念、追更理由、状态连续性、关系变化、分享连续剧。

### 内容比例建议

- 50% 单日轻事件
- 30% 持续事件推进
- 15% 关系变化
- 5% 稀有大事件

## 十、UGC 的定义

内容生产公式：

用户设定 + 猫的长期状态 + 世界模拟结果 + AI 叙事加工 + 用户确认 = **角色生成型 UGC（Character-generated UGC）**

用户不从零写内容，而是：创造角色、持续影响角色、选择故事版本、添加一句评论、决定是否发布。内容是用户和 AI 猫共同"生活出来"的。

## 十一、UGC 内容体系

1. **私密型内容**（服务留存和情感关系）：每日日记、猫给主人写的留言、本周心情总结、关系变化、成长纪念、主人记忆回顾。
2. **岛内展示内容**（服务浏览和角色认知）：猫咪动态、NPC 对话、岛屿新闻、战利品、消费账单、状态变化、趣味失败。
3. **外部传播内容**（服务获客）：人格梗、反差梗、连续剧、创业失败、社恐日常、情绪共鸣、岛屿职场、猫咪关系冲突。外部内容必须：三秒内可以看懂；不依赖产品背景；有明确人格；有冲突或情绪；单独拿出来也成立。
4. **二期共创内容**（MVP 不做）：用户提交事件、设计服装和房屋、给 NPC 命名、设计岛屿节日、投票决定公共事件、多只用户猫参与共同剧情。

## 十二、内容生产管线

模拟事件发生 → 内容价值评分 → 选出今日主事件 → 选择表达形式 → 生成多个版本 → 内容去重和安全审核 → 用户轻量选择 → 发布或分享 → 数据反馈给导演系统

### 内容价值评分

主要考虑：意外性、人格一致性、情绪强度、历史关联、社交冲突、稀有程度、可理解性、分享潜力、与持续事件线的关系。不是每件日常小事都值得生成内容。

### 表达形式

同一个事实可以生成：猫咪第一人称日记、主人吐槽、NPC 聊天截图、岛屿新闻、消费账单、失物招领、四格漫画脚本、短视频旁白。

MVP 先保留三种：**每日日记、猫咪动态卡、外部分享卡**。

## 十三、视觉和角色一致性

用户必须始终认得"这是我的猫"。MVP 不应每天重新生成整只猫，而应采用：

一张固定主立绘、四个表情差分、三个基础动作、六个通用场景、若干道具和前景、模板化分享卡合成。

这样能够：保证角色一致性、降低生成成本、提高分享卡稳定性、强化 IP 归属感。

后续再开放：AI 写真、漫画、视频、实体玩偶、定制纪念册。

## 十四、商业化路径

MVP 阶段不做复杂数值付费。第一批商业化围绕身份和情感资产：

猫咪皮肤、小屋主题、装饰和服装、高清分享卡、月度纪念册、AI 写真、第二只猫、更长记忆、特殊事件和岛屿主题。

长期商业化：定制玩偶、亚克力和摆件、日历和绘本、热门 NPC 周边、品牌联名、IP 授权。

**不建议过早售卖**：行动力、加速、鱼币、数值强化——否则产品容易从情感陪伴变成传统资源游戏。

## 十五、技术架构

```
用户干预
    ↓
岛屿导演 Director
    ↓
世界模拟器 World Engine
    ↓
用户猫 Agent / NPC Agent
    ↓
结构化状态 + 关系 + 记忆 + 目标
    ↓
事实事件日志
    ↓
内容评分与编辑
    ↓
日记 / 岛屿动态 / 分享卡
```

核心数据对象：User、Cat、CatState、Personality、NPC、Relationship、Inventory、Location、EventTemplate、SimulationEvent、EventThread、Memory、Reflection、DailyPlan、Narrative、ContentArtifact、ShareRecord。

## 十六、MVP 范围

### 第一版必须完成

- 创建一只固定形象的猫
- 结构化人格
- 猫的状态系统
- 12—16 个 NPC
- 简单关系系统
- 事件模板
- 持续事件线
- 每日三段模拟
- 基础记忆检索
- 关键节点反思
- 一篇每日日记
- 一至两条岛屿动态
- 一张分享卡
- 用户轻量干预
- 埋点和留存分析
- 内容审核和隐私控制

### 第一版明确不做

开放世界自由移动、实时游戏操作、真人用户聊天、跨用户猫咪自由社交、玩家猫互访、自由交易、多只猫同时养成、全量 UGC 创作工具、每日整图 AI 生成、自动短视频生产、复杂经营系统、完整数值付费、全部 NPC 完整 Agent 化、24 小时实时模拟。

## 十七、产品验证路径

### 阶段一：模拟器验证

先不做完整网站。在后台连续模拟同一只猫 30 天，观察：

状态是否自洽；角色是否保持人格；事件是否重复；剧情是否有连续性；NPC 关系是否可感知；是否出现数值和事实冲突；30 天内容是否仍然耐看。

### 阶段二：小规模 Web MVP

开放给 30—100 名种子用户。只验证：是否创建猫；是否连续回来；是否记得角色和 NPC；是否分享内容；第几天开始感到重复；是否产生牵挂。

### 阶段三：分发适配

验证成立后再依次考虑：Web MVP → 微信内 H5 → 微信小程序 → 独立 App。

分享卡从第一天就应预留：回流链接、二维码、猫咪唯一 ID、渠道归因参数。

## 十八、建议的成败标准

| 指标 | 低于此值需重做 | 值得继续 |
| --- | --- | --- |
| 创建完成率 | 60% | 75% 以上 |
| D1 留存 | 25% | 40% 以上 |
| D3 留存 | 12% | 25% 以上 |
| D7 留存 | 8% | 15% 以上 |
| 主动分享率 | 3% | 8% 以上 |
| 七日人均查看次数 | 3 次 | 5 次以上 |

定性信号：用户是否记住 NPC 名字；是否担心猫之后会怎样；是否主动保存故事；是否给朋友展示自己的猫；是否会因为猫的选择产生情绪；是否催促第二天内容；是否主动要求增加新功能。

## 十九、项目长期方向

1. **第一阶段**：AI 猫电子宠物。
2. **第二阶段**：AI 猫咪岛屿社区，用户猫之间发生有限互动。
3. **第三阶段**：热门猫和 NPC 形成稳定 IP，延伸至漫画、视频和实体周边。
4. **第四阶段**：底层扩展为虚拟生命平台，支持狗、精灵、怪兽、虚拟偶像、用户自定义角色。

但第一阶段不应该用"虚拟生命平台"的宏大目标指导研发，仍然只验证一只猫是否值得用户连续看七天。

## 二十、最终定义

猫啊岛不是：猫咪资讯站、猫咪内容社区、AI 聊天机器人、AI 图片生成工具、传统模拟经营游戏、斯坦福 AI 小镇的猫咪换皮。

猫啊岛要做的是：

一座持续运行的小型 AI 模拟世界。每个用户领养一只拥有固定身份、长期记忆、独立人格和持续关系的 AI 猫。猫在用户不在线时也会自主生活，系统将真实发生的状态变化和关系演化加工成日记、动态与分享内容，让用户形成牵挂，并通过角色生成型 UGC 完成传播。

核心技术公式：**Generative Agents + 游戏状态机 + 事件系统 + 剧情导演 + AI 内容管线。**

核心产品公式：**持续生活产生牵挂，独特经历产生内容，可分享内容产生增长。**

核心执行原则：**先做一个能够连续稳定运行 30 天的猫咪模拟器，再做完整产品。**
