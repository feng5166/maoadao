# doc/11 让它找到你——微信生命连接层(openclaw)

> 2026-08-01 拍板。承接 doc/09(生命 IP 校准)与 doc/10(D1 相遇重构)。
>
> **一句话定义:微信不是猫啊岛的客户端,而是 AI 猫与主人之间的"现实连接通道"——
> 负责召回、关系维系和轻互动,让猫在用户离开网站后仍然存在。**
>
> 当前阶段(Web 验证、不做 App、小团队冷启动),它是核心基础设施,价值排序:
> ① 提升 D2/D7 留存(召回) ② 增强"猫真的活着"的感知 ③ 形成主人与猫的长期记忆 ④ 为多人 AI 世界建立现实入口。

## 一、解决什么问题

猫啊岛最大的天然缺陷:用户第一次觉得有趣,离开网页后没有理由回来——没有 App 桌面入口、没有 Push。
**D1 最大的流失风险不是用户不喜欢猫,而是离开网站以后忘记回来。**
微信的答案:不靠用户记住猫,靠**猫找到主人**。关系方向反转:普通 AI 是"用户打开→AI 回复";猫啊岛是"猫生活→想起主人→联系主人"。

## 二、分工边界

**Web 是猫的世界**:看生活/完整故事/岛屿/历史/图片/深度互动。
**微信是猫和主人之间的线**:猫想起主人、告诉主人一件事、主人回一句话、这句话影响未来生活。

微信明确不承担(openclaw 是文本通道,不是富媒体应用):猫主页、日记列表、岛屿地图、图片社区、复杂 UI、游戏玩法——这些全部回 Web。
微信只做:文本陪伴、关键事件提醒、用户回复输入、关系维护。

## 三、D1 重定义:第四资产与新漏斗

**领养成功 ≠ 完成注册;微信绑定 + 第一次互动完成,才算建立主人关系。**
D1 四资产同级:猫名、第一句话、相遇照片、微信绑定。

```
船票进入 → 遇见猫 → 领养 → 第一次留言 → 绑定微信(让它找到你)
→ 猫承诺明早告诉你 → 离岛仪式 → 微信召回 D2 → 回岛
```

D1 完成标准:领养 + 第一句话 + 绑定 + 约定明天见,四件齐才算 D1 成功。

## 四、绑定设计

### 命名
永远不叫"开启微信通知"(用户翻译成广告),叫**「让它找到你」**——这是世界观内的关系动作。

### 时机(两次曝光,不再多)
1. **主曝光:第一次留言的确认屏**——"煤球记住了你的第一句话"是情感峰值点,CTA 直接接在峰值上:
   「明天它醒来后,想第一时间告诉你。——加上它的微信:」
2. **二次曝光:离岛仪式页(明天见)**——注意时态诚实:用将来时预告("今晚它会把你的话放在床边,明早醒来第一件事就来告诉你"),不把未发生的傍晚写成已发生(守 doc/09 的现在感)。

绑定先于留言的变体:握手消息去掉引用段,反向引导"你还没跟它说过话——回岛上给它留一句?"

### 暗号配对(个人号桥无 OAuth)
```
Web:  [微信二维码] + 口令「红绳-483」(纪念物词-三位数,一键抄下)
微信:  加好友 → 发口令 → 后端配对 wxid↔userId → 立即发握手消息
Web:  配对成功后页面出现「✓ 它找到你了。」(justDone 同款庆祝待遇)
```
口令错发容错:"口令不对,再看一眼你家猫的页面?"

### 兜底
入岛三件事第三件改为**「给它留一个能找到你的方式」**:微信优先,邮箱(已有 notifyDaily)次选——微信排斥型用户不走死路。已绑微信者停发每日邮件,双通道不叠加。

## 五、1:1 直连身份

**每个绑定关系是 1:1 的:用户的对话框里只出现自己猫的话。**
- 账号档案中性化(昵称"猫啊岛"/爪印头像),不自称任何一只猫;
- 每条消息以「🐱 煤球:」开头,全文第一人称,口癖系统(doc/09 §6)照用——用户体感是"我微信里有我的猫";
- 天然兼容未来第二只猫(付费点):同一对话框、两个前缀;
- 换号容灾叙事只需一行:"它换了个信箱给你寄信"。绑定资产落 userId,不落微信号。

**"猫啊岛的猫会加你微信"——这句话本身就是传播点。**

## 六、消息设计

### 原则
**不发通知,发"猫的生活"。** 错:"您的猫今日更新"。对:"煤球:今天经过码头的时候,我想起了你第一天告诉我的话。"

### 四种消息类型
1. **想起主人**(强化关系):"今天晒太阳的时候,我突然想起你。"——必须挂在真实事实上(当日事件+记忆回响机制),低频,不粘人;
2. **需要主人意见**(增强参与):"阿福邀请我去灯塔,我有点犹豫。"——对接动态剧情选择/nudge,注意频次,不能变成每日任务 ping;
3. **分享小发现**(情绪价值):Life Moment 池的天然出口;
4. **重要事件**(推动回流):"那把红绳钥匙终于打开了一扇门。"——带链接回 Web。

### 事实红线
**微信消息和日记走同一条叙事管线:模拟器产事实,LLM 只包装,绝不编造。**
猫默认不知道现实侧信息(头像、地理位置)——"像你头像颜色的叶子"这类内容,只有把该信息在绑定时作为事实写入主人记忆后才合法(可选项:绑定日落一条"主人的头像是橘色的"事实,之后偶尔回响,惊喜感极强)。

### 消息日历
| 时机 | 内容 | 说明 |
| --- | --- | --- |
| D1 绑定即刻 | 握手:引用第一句话 +"明早第一件事告诉你" | 唯一即时消息 |
| D2 早八后 | **兑现承诺**:今晨第一件事 + 链接 | 内容取自今晨真实事实(morning 主事件 + 回应摘句),首日心理契约的兑现,必发 |
| D3 起 | 事件触发白名单:第一次交到朋友/事件线关键步/D7 纪念册/店开张 | 每天 ≤1 条,无事不发 |
| 缺席 3 天 | "它没什么事,就是今天多看了两眼码头" | 不责备体(v0.8 缺席原则),留存金矿 |
| 静默时段 | 22:00–8:00 不发;发送时间 8:00–8:40 随机打散 | |

### 窗口机制(自律窗口)
个人号桥技术上无硬性窗口——这里的窗口是**产品纪律**:用户互动→打开交流窗;主人长期不回应→猫继续生活、降频等待(像真实关系:回应多,猫更愿意靠近)。同时为将来迁服务号(存在真实 48h 窗口)提前兼容行为模式。

## 七、双向:回信即留言

openclaw 是双向通道——**在微信里回猫一句话,就是一次留言(nudge)**,这是比推送更值钱的一半:
- 回信 → 落为当天 ownerNudge → 明早 tick 消费 → 回应出现在日记里,并由微信捎回;
- 即时 ACK 用猫第一人称**确定性短句**(摸摸它同款机制,按心情换池):"记住啦。明早说给你听。"
- **绝不接续聊天**(砍聊天原则不动摇):连发多条只合并为最新一条,提示"一天捎一句,它记性好";
- 微信把留言成本从"打开网站写一段"降到"回一句话"——首日干预率的主要抓手。

## 八、openclaw 技术约束与运维红线

1. **哑管道红线**:openclaw 本体的 LLM 自动回复必须关闭。收到消息→回传猫啊岛后端;发出消息→只发叙事管线产物。任何一句猫的话都不允许由通道层生成。
2. **通道抽象**:数据模型为 用户↔通道(wechat_openclaw | email | 未来服务号),绑定资产永远落 userId。
3. **定性**:openclaw 是内测阶段的验证工具,不是终局基建。绑定率与 D2 唤醒率验证成立后,正规化路径 = 认证服务号 + 模板消息;不成立则省下这笔申请。
4. **防封号清单**:每人每天 ≤1 条;内容千猫千面(天然无群发特征);链接不每条带(握手不带,D2 带);单号好友数控制在内测规模;送达失败率/被拉黑数进监控,连续异常**自动停发**——个人号桥的死法通常是没人看着它。

## 九、指标

- **微信绑定率** = 绑定 / 完成领养,目标 30–50%(核心新指标,与 first_words_submit 同级);
- **绑定三段漏斗**:点击"让它找到你" → 加好友 → 口令配对成功(掉哪段修哪段);
- **D2 微信唤醒率** = 收到消息后回访 / 绑定用户(微信价值的判决指标);
- **点击回流率** = 点击链接 / 消息发送;
- **微信侧留言占比** = 微信回信 nudge / 全部 nudge;
- 负向监控:拉黑数、取关(删好友)数、送达失败率。

## 十、与长期路线的关系

- **Phase 1 单猫陪伴(现在)**:微信 = 召回 + 建关系,证明"用户愿意关心一只 AI 猫";
- **Phase 2 猫认识猫**:微信告诉主人"你的猫和另一只猫发生了什么";
- **Phase 3 AI 社会**:微信 = 现实世界入口(NPC 联系主人/岛屿事件/节日/多人关系)。
架构方向:AI World → Character Agent → Personal Channel → 微信。

## 十一、明确不做

- 每天固定推送(D2 除外);
- 微信内自由聊天 / openclaw 代猫说话;
- 微信承载任何 Web 职能(主页/列表/地图/玩法);
- 群发运营消息、营销文案——这个号里只有猫的生活。
