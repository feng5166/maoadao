# 海螺 24h 窗口保活设计(v1,2026-08-04)

> 平台铁律:只能在用户最后一次说话后 24h 内发消息(windowOpenUntil),无法绕过。
> 数学:用户每天任意时刻回一句,即可保住次日早安(8:00)与晚安(21:00)。
> **设计目标只有一个:每天换取一次"真心想回"的回复——不是打卡,是对话。**

## 一、拉力:让回复有回报(核心循环)

```
21:00 晚安(带轻钩子) → 用户睡前回一句 → 窗口 +24h
    → 次日 8:00 早安开头带"昨晚回执感" → 用户看到自己的话被记住
    → 晚上又想回 → 循环
```

1. **晚安带轻钩子**:尾巴池里一部分是可回应的("你要是还没睡,跟我说一声。")——
   回复即触发既有的留话/回执链路(海螺把话记下,明天日记回应),回复本身有叙事回报。
2. **早安回执感**:昨晚(18:00 后)说过话的用户,早安开头多一句"昨晚你说的话,我睡前又看了一遍。"
   ——用户第一次发现"回它是有用的",习惯从这里长出来。
3. **回复接入建议系统**(既有):用户的话会被猫记住并影响明天,不是聊天而是养育。

## 二、推力:断链的情感召回

窗口关了 → 早安/晚安落成 `window_closed` = **"它写给你、没寄出去的信"**(既有机制):
- /my-cat 已展示未寄出的信 + "对着海螺说句话,信就能寄到——隔太久没动静,海螺会睡着。"
- 用户在网页看到猫昨晚没送出去的晚安 → 心疼 → 回一句 → 链路复活。
- 网页是不受窗口限制的召回面;分享卡/今日页都是回流入口。

## 三、红线(微信反 spam + 产品气质)

- 不发"回复 1 领取"式打卡诱导;不连发多条求回复;不假装紧急。
- 钩子必须是猫的自然话,回不回都成立;窗口关了安静跳过,绝不硬发。
- 每天最多早安+晚安两条(事件信占早安位),永不加量。

## 四、指标

- 窗口存活率 = windowOpenUntil > now 的绑定用户占比(watch 每日)
- 回复率 = 晚安发出后 12h 内有 inbound 的比例
- 断链恢复 = window_closed 后 72h 内窗口重开的比例
