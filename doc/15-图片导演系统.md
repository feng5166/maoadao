# doc/15 图片导演系统——从"生成事件图片"到"世界资产 + 动态组合"

> 2026-08-04 拍板。猫啊岛的第三块拼图：模拟器负责生命，叙事负责语言，**视觉资产系统负责画面**。
> 方向转变：不再追求"每个事件生成一张新 AI 图"，改为建立可长期运行的数字生命视觉资产系统——
> AI 当导演，素材保稳定。否则 100 猫 × 每天 1 图 = 年 3.6 万次生成，成本必然失控。

## 一、核心认知

1. **意义来自状态，不来自新图**。真实养猫的照片也是沙发/窗边/阳台的重复，因为时间和状态不同才有意义。
   第一天猫怕生地蹲在灯塔下，第十天带朋友再去——同一张灯塔，两种人生。允许重复。
2. **水彩绘本风是天然优势**：不要求每根毛一致（3D 写实才要求），素材拼贴毫无违和——手账贴纸本来就是拼的。
3. **成本结构目标**：80% 程序合成（零生成成本）/ 15% 局部 AI（带锚点改图）/ 5% 全新生成（高价值时刻）。

## 二、五层资产结构

| 层 | 内容 | 频率 | 存放 |
| --- | --- | --- | --- |
| L1 猫角色 | 每猫姿势集：坐/趴睡/行走/玩耍/远眺（立绘风格锚点保同猫） | 领养时一次 | DB `CatPose`（同 Portrait 模式） |
| L2 场景 | 9+ 固定场景 × 4 时段（清晨/白天/黄昏/夜晚） | 一次投入 | `public/scenes/{name}.jpg` + `{name}-{time}.jpg` |
| L3 动作 | 钓鱼/看海/喝茶/看书/修东西……（姿势集的扩展位） | 中频补充 | 并入 CatPose（pose 枚举扩展） |
| L4 物件 | 鱼竿/贝壳/旧钥匙/小船/花/书（贴纸小图） | 高复用 | `public/props/`（待建） |
| L5 特殊事件 | 相遇/D7 纪念/重大剧情/节日——**只有这里调用全新生成** | 低频高价值 | 现有 arrivalPhoto 等 |

## 三、导演管线

```
事件(模拟器) → 视觉导演(lib/visual/director.ts) → 组合谱(CompositionSpec) → 合成器(lib/visual/compose.ts) → 图
```

- **导演**：纯规则起步（location→scene 沿用 handbook 映射；segment→时段；mood→姿势倾向；事件类型→贴纸道具）。
  确定性(seed=catId+day)——同一天同猫永远同一张，天然可缓存。LLM 导演是后续升级位，不是 v1。
- **组合谱**：`{scene, time, pose, tint, prop?}`——全部是资产 ID，不含生成指令。
- **合成器**：sharp 拼贴——场景底图 + 猫姿势"手账贴纸"（白边+微旋转，回避抠图/alpha 问题）+ 时段色调层
  （复用 CSS fx-dawn/fx-dusk 的色值）。输出即缓存（同谱同图）。

## 四、v1 范围（支撑 D1 + 海螺 + 分享）

1. L2 时段变体：核心场景 × 黄昏/夜晚/清晨（白天=现有图）。锚点=该场景现有图（保构图）+ 画风锚。
2. L1 姿势集：每猫 5 姿势（sit/sleep/walk/play/lookout），立绘做参考图（同猫一致），领养后异步生成。
3. director + compose 骨架与缓存表（`ComposedImage`，同谱免重算）。
4. 第一个消费方：手账页场景图升级为"场景时段变体 + 猫贴纸"（替代现在的固定下午图 + 圆头像叠加）。
   海螺日签/分享卡接入放 v1.1。
5. 尺寸纪律：资产 2048 存档，线上 WebP 480/720 两档；海螺 720×720。

**暂不做**：物件层（L4）、LLM 导演、游戏化骨骼动画管线（远期方向，动物森友会式；等验证复用体感后再议）。

## 五、成本账

- 一次性：9 场景 × 3 时段 = 27 张 + 每猫 5 姿势（现存量 ~20 猫 = 100 张）≈ 130 次生成，一次投入。
- 增量：新猫入岛 +6 张（立绘+5 姿势）；日常生活图 **0 生成**（全部程序合成）；
  特殊时刻（L5）才动生成，每猫每月 1-2 张封顶。
- 对照旧路线：100 猫全生成 = 3000 张/月 → 新路线 ≈ 150-200 张/月，降一个数量级。

## 六、验收

同一只猫在同一场景的清晨和夜晚各合成一张——用户看到的是"它的一天"，成本是零次生成调用。
